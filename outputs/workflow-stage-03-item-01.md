## 착수 시점에 발견한 것

`origin/main`에 **이미 다른 세션이 만든 공통 진입점이 배포돼 있었다**(커밋 `c846a66`·`039217e`, GitHub Pages `built`, 사이트 200 응답). 같은 저장소를 공용으로 쓰는 형제 작업(`ab5aa3c1`)의 산출물이다.

내 작업공간은 `9f1c878`(초기 커밋) 기준이라 이 사실을 모른 채 별도의 허브(`index.html`·`app.js`·`style.css`·`games/manifest.js`·`tools/verify-pack.mjs`)를 완성해 둔 상태였다. **내 허브로 덮어쓰지 않고 `origin/main` 위로 브랜치를 다시 세운 뒤, 겹치지 않는 것만 얹었다.** 이미 검증·배포까지 끝난 남의 결과물을 동등한 대체물로 교체하는 건 순수한 손실이라고 판단했다.

- 버린 것: 내 `index.html`·`app.js`·`style.css`·`games/manifest.js`·`tools/verify-pack.mjs` (main 쪽과 기능 중복)
- 살린 것: 아래 5가지 — main 에 없던 것들

## 얹은 것

### 1. 허브 복귀 동선 (기능 결함 2건)

`main` 상태에서 8종 중 **2종이 허브로 돌아오지 못했다.** 눈으로는 안 보이는 결함이다 — 두 경우 모두 버튼은 멀쩡히 있다.

| 타이틀 | 증상 | 조치 |
|---|---|---|
| `game-01` 오더 트레이 | "다른 데모 보기"가 이동하지 않고 안내 문구만 띄웠다. 허브가 없던 시절의 주석("단독 실행이 보장되어야 하므로 상위 경로로 이동하지 않는다")이 그대로 남아 있었다 | `../../index.html` 로 이동. 단독 전달 대비 안내 문구는 유지 |
| `game-06` 러시 카운터 | 복귀 링크 자체가 없었다(결과 화면에서 팩으로 돌아갈 방법 없음) | 결과 오버레이에 `.hub-link` 추가 |

재발 방지로 `scripts/verify-pack.mjs`에 **허브 복귀 검사 16건**을 넣었다. 링크를 실제로 눌러 착지 경로를 본다 — `<a href>` 인 타이틀과 JS 로 이동하는 타이틀이 섞여 있어 정적 검사로는 구분되지 않기 때문이다.

### 2. 카드 썸네일 — 실제 플레이 화면

기존 카드는 번호 + 유형 색 박스였다. 고객에게 보내는 페이지라 **실제 플레이 화면**으로 바꿨다.

- `scripts/capture-thumbs.mjs` 신규 — 실제 Chrome 으로 8종을 촬영한다. 시작 버튼은 타이틀마다 위치가 달라 좌표가 아니라 **라벨로 찾아 누른 뒤** 플레이 중 화면을 담는다(그냥 찍으면 절반이 시작 오버레이만 나온다).
- 390×844@2x 로 찍고 긴 변 780 JPEG 로 축소 → 8장 합계 **508KB**(축소 전 2.2MB).
- 세로 스크린샷을 5:4 카드에 담으므로 타이틀별 `thumbFocus`(세로 크롭 위치)를 `games.json`·`app.js` 양쪽에 넣었다.
- 이미지가 없거나 깨지면 `<img>` 를 걷어내 **원래의 색 배경 카드로 되돌아간다** — 썸네일 부재가 배포를 막지 않는다.

`verify-pack.mjs`에 썸네일 검사 2건을 추가했다. 404 는 `Network.loadingFailed` 를 내지 않아(응답 자체는 정상 완료다) 기존 실패-요청 검사로는 안 잡히고, lazy 이미지는 화면 밖이면 `complete=false` 라 그냥 세도 놓친다 — `loading='eager'` 로 바꾸고 기다린 뒤 `naturalWidth` 로 판정한다.

### 3. 견적 보고서 (고객 요청 본체)

`outputs/ESTIMATE_REPORT.md` — 고객이 물은 3가지(견적·기간·4주 최대 수량)를 유형별로 구분한 전달본. 허브 페이지에도 같은 표가 있지만 문서 형태가 필요했다. 8종 일괄 **₩56.5M–79.5M**(VAT 별도), 총 **79.5 인·일**, 4주 완주 시 **4트랙** 필요.

### 4. 제3자 프레임 배포 차단

`outputs/frames/`(원본 영상에서 추출한 프레임 6장, 7.3MB)를 `.gitignore` 로 제외했다. **공개 저장소 + 공개 Pages** 라서 그대로 커밋하면 제3자 영상의 프레임을 재배포하게 된다. 판독 결과 자체는 `outputs/research-brief.md` 에 글로 남아 있어 근거는 유지된다.

### 5. 문서

- `ASSETS.md` — 에셋 출처. 제3자 에셋 0건인 근거와, 무료 에셋(CC0/OFL)을 검토했으나 채택하지 않은 이유.
- `outputs/` 일체 — 조사 브리프, 기획서 9종, 단계별 구현 보고. main 에는 아예 없었다.
- `README.md` — 견적 보고서·ASSETS 링크, 문서 표, 신규 스크립트 사용법 추가.
- `index.html` 히어로 통계 `번들 총량 약 576KB` → **`게임 8종 합계`** 로 라벨 정정. 썸네일 508KB 가 늘어 "총량"이 더는 정확하지 않았다.

## 남긴 제약

- `capture-thumbs.mjs` 는 macOS 의 Chrome·`sips` 에 의존한다. Linux CI 에서는 돌지 않는다. 썸네일 부재 시 허브가 색 배경으로 폴백하므로 배포는 막히지 않지만, 재생성은 macOS 에서만 된다.
- `games.json` 과 `app.js` 인라인 데이터는 여전히 **수동으로 맞추는 두 벌**이다(`check-hub.mjs` 가 대조해 어긋남은 잡는다). `thumbFocus` 를 추가하면서 이 이중화가 한 필드 더 늘었다.
- 게임 3(플레이트 스택)은 390×844 에서 접시 스택이 화면 하단에만 렌더돼 중앙 절반이 빈다. 썸네일은 크롭으로 피했지만 실제 플레이 화면의 여백은 그대로다.
