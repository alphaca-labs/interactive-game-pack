프레임에서 **확정되지 않는 것**은 임시 보관 슬롯 개수, 라운드 시간, 코인 산식, 클리어 조건이다. 이 4가지는 20–45초 프로토타입 기준의 독자 설계로 명시하고, 기획서를 단일 기준으로 고정했다.

## 확정한 설계 핵심

| 항목 | 값 |
|---|---|
| 보드 | 6컬럼 × 4장 = 접시 24장, 컬럼당 최상단 1장만 탭 가능 |
| 주문 | 총 8건(24 = 8 × 3), 각 주문 = 동일 요리 3장, 카운터 활성 2건 |
| 보관 트레이 | 3칸. 탭한 접시는 항상 트레이 경유 → 해소 패스로 활성 주문에 자동 충전 |
| 실패 | 해소 패스 후에도 트레이 3칸이 막힘, 또는 60초 초과 |
| 클리어 | 접시 24장 전량 소진 |
| 점수 | 주문 기본가(40/80/120/200/300) × 콤보 배수(1.0→1.2→1.5) + 잔여 시간 × 5 |
| 조작 | 컬럼 = 실제 `<button>`, 6개를 `role="toolbar"` 로 묶어 Tab 1회 진입 + `←/→` 이동 + Enter/Space 픽 |

## 이 소재의 결정적 리스크와 대응

**무작위 셔플은 트레이 3칸으로 풀 수 없는 배치를 만든다.** 그 실패는 플레이어에게 "내 실수" 가 아니라 "게임 탓" 으로 읽혀 광고 소재로서 치명적이다. 대응으로 **역방향 생성**을 규정했다 — 정답 픽 시퀀스를 먼저 만들고(트레이 점유 2 이하 범위에서만 인터리브) 그것을 역순으로 컬럼에 쌓으면, 역순 push = 정방향 pop 이므로 그 수순이 **반드시 유효**하다. 시드 기반이라 QA 재현이 가능하고, 생성 직후 정답 수순을 규칙 엔진에 그대로 돌려 자체 검증한다(실패 시 최대 20회 재생성 → 검증된 고정 시드로 폴백).

두 번째 리스크는 **주문 완료 → 손님 교체 → 트레이 재해소** 로 이어지는 상태 전이 연쇄다. `pick / resolve / isLost / isCleared` 를 DOM 무관 순수 함수로 분리해 보드 생성 검증기와 게임 본체가 같은 코드를 쓰게 했다.

세 번째는 **요리 6종 변별력**이다. 색상 단독이 아니라 색상 + 실루엣 + 보조 형태 3중으로 구분하고 주문 카드에 요리 이름 텍스트를 항상 병기하도록 규정했다.
