## 기획서 대비 구현 사항

- 조리도구 **8종 × 3개 = 24개**, 12종 라이브러리에서 시드로 선정, 4열 × 6행 논리 앵커 배치.
- **7칸 정리 바구니**, 동일 종류 3개 자동 제거, **35초** 제한, 8세트 전량 제거 시 성공.
- 점수: 트리플 100점 · 4초 내 연속 `+25 × 단계`(3단계 +75 상한) · 성공 시 `남은 초 × 10` · 힌트 −100(하한 0).
- 힌트는 7초 무진행 시 1회 활성, 완성 가능한 종류를 1.2초간 **테두리 + ◆ 심볼**로 표시(색 단독 의존 없음).
- 포인터·터치·키보드가 모두 `selectTool(id)` 하나로 진입해 점수·시간·판정이 동일하다.
- `?seed=` 재현, `?test=1` 자동 검증, `?relax=1` 여유 모드.
- 흩어진 느낌은 셀 안쪽의 제한된 흔들림(±10%/±8%)과 회전(±10°)으로만 만들고, 그 상한을 셀 간격보다 작게 잡아 **hit area 비중첩과 44px 하한을 배치 규칙 자체로 보장**한다.

### 판정 순서 (회귀 위험 지점)

```
입력 재진입 잠금 → 도구 이동 → 트리플 탐색·제거 → 성공 확인 → 바구니 초과 확인 → 잠금 해제
```

바구니 초과 확인을 앞으로 옮기면 **일곱 번째 도구가 트리플을 완성해도 실패 처리**된다. 화면상으로는 «가득 찼어요» 결과가 정상적으로 뜨기 때문에 버그로 읽히지 않는다. `selectTool()`의 코드 순서와 자동 검증의 「7번째가 트리플이면 실패하지 않음」 검사가 관문이다.

`selectTool()`은 전 구간이 동기라 rAF 타이머가 중간에 끼어들 수 없다. 마지막 탭과 35초 만료가 겹쳐도 탭 처리가 먼저 끝나고 `finishOnce()` 단일 가드가 뒤따르는 시간 종료를 무시한다.

## 구현 중 실제로 찾아 고친 결함 5건

기획서대로 짜는 것만으로는 잡히지 않고 브라우저 실측에서 드러난 것들이다.

1. **HUD 가로 오버플로 (4개 뷰포트)** — 고정 3열 그리드라 최소 폭이 358px여서 320×568·844×390·768×1024·200% 확대에서 가로 스크롤이 32~157px 생겼다. 좁으면 통계 3종이 둘째 줄로 내려가도록 flex-wrap 구조로 바꾸고, 아주 좁은 폭에서는 힌트 비용 표기를 접었다(값은 상태 문구·결과에 남는다).
2. **AudioContext autoplay 경고 다발** — 사용자 제스처 없이 `AudioContext`를 만들어 호출마다 Chrome 경고가 쌓였다(`?test=1`에서 100건 이상). 첫 `pointerdown`/`keydown`에서만 생성하도록 바꿨다.
3. **한국어 조사 하드코딩** — `«거품기을(를) 담았습니다»`. 받침 유무로 조사를 고르는 `particle()`을 넣고 12종 전량을 자동 검증에 넣었다.
4. **벽/바닥 경계 어긋남** — 배경 그라디언트를 38%에 고정해 카운터 위치(`--counter-h`)와 따로 놀았다. 경계를 `--counter-h` 기준으로 통일했다.
5. **창과 싱크 겹침** — 둘 다 왼쪽에 배치돼 하나의 정체불명 도형으로 보였다. 창·레일·싱크·레인지를 가로로 분리하고 창살·수전·화구를 넣어 형태를 알아볼 수 있게 했다. 낮은 화면에서는 장식을 접고 카운터 선만 남긴다.

또한 초기 배치가 지나치게 성겨 보여 도구 크기를 화면 폭·높이를 함께 보는 `clamp(44px, min(16vw, 8.4vh), 66px)`로 키웠다(44px 하한과 비중첩은 유지).
