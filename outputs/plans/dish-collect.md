# 디시 컬렉트(Dish Collect) 제작 계획

## 1. 기획 기준과 플레이어 약속

- **관찰 근거:** 원본 `01:52`(`outputs/frames/group2-112s.png`)와 `02:40`(`outputs/frames/group2-160s.png`)의 네 번째 패널, 그리고 확대 프레임 `outputs/frames/g8-detail.png`를 직접 판독했다. 확인된 것은 ① 상단 하늘 배경 위의 **큰 접시 1장에 목표 요리 1종**, ② 하단 **연한 체크무늬 격자 보드에 흩어진 식재료 아이콘 다수(빈 칸 섞임)**, ③ 커서가 놓인 칸에서 **재료가 반짝이며 사라지고 금색 파티클 궤적이 위쪽 접시로 상승**, ④ `01:52`의 가득 찬 보드가 `02:40`에는 대부분 비고 **접시의 요리가 다른 것으로 교체**된 상태다.
- **확정된 핵심:** 목표 요리가 요구하는 재료를 격자 보드에서 눈으로 찾아 탭해 접시로 수집하고, 요리가 완성되면 다음 요리로 교체되는 세로형 미니게임이다. 보드는 소비되기만 하고 **판 중간에 다시 채워지지 않는다**(두 프레임 사이에 재료가 늘어난 흔적이 없다).
- **구현 가정(원작 재현 주장 아님):** 프레임만으로는 요구 수량 표기, 오답 처리, 제한 시간, 점수 규칙을 판별할 수 없다. 이 프로토타입의 기준은 **요리 4개 연속 서빙 · 요리당 재료 5개 · 40초 제한 · 오답은 타일 제거 없이 시간 차감**으로 고정한다.
- **한 줄 약속:** 접시에 뜬 요리를 보고, 어수선한 재료 격자에서 필요한 것만 골라 빠르게 네 접시를 완성한다.
- **차별점:** 같은 Type A인 `winter-pantry`는 "한 종류를 지정 수량만큼", `kitchen-tidy`는 "같은 것 3개 매칭"이다. 이 게임은 **여러 종류 × 각기 다른 수량의 레시피를 순차로 처리**하는 것이 고유 축이며, 지금 필요 없는 재료를 참는 판단이 재미의 중심이다.
- **톤:** 맑은 하늘 위에 떠 있는 접시, 파스텔 체크 보드, 또렷한 음식 실루엣과 금색 수집 궤적. 원본 로고·캐릭터·UI 캡처·추출 에셋·음원은 일절 사용하지 않는다.

## 2. 1라운드 코어 루프(약 28~36초)

1. **도입 0~3초:** 보드 36개 재료가 6열×8행 체크 격자에 배치되고, 상단 접시에 첫 요리와 요구 재료 카드가 뜬다. `접시에 필요한 재료를 찾아 탭하세요` 안내와 함께 첫 요구 재료 1개를 최대 두 번 은은하게 강조한다.
2. **탐색·수집 3~30초:** 필요한 재료를 탭하면 타일이 반짝이며 보드에서 사라지고 금색 궤적을 그리며 접시로 올라간다. 요구 카드의 해당 재료 수량이 1 줄어든다.
3. **판단 압박:** 지금 요리에 필요 없는 재료를 탭하면 타일은 그대로 남고 시간만 깎인다. 다음 요리 미리보기를 보고 "지금 참을 재료"를 구분하는 것이 핵심 판단이다.
4. **요리 교체:** 요구 수량이 모두 0이 되면 접시가 완성 연출 후 다음 요리로 교체되고 진행이 `1/4 → 2/4`로 오른다.
5. **종료 30~40초:** 네 번째 요리를 완성하면 성공한다. 40초가 끝나면 실패한다. 결과 화면에서 즉시 다시 하기와 비상업용 `다른 데모 보기`를 제공한다.

첫 판은 첫 요리의 요구 재료를 보드 상단 절반에 몰아 배치해 학습을 돕고, 재시작부터는 같은 규칙 안에서 새 시드로 섞는다. 결과 확인을 포함한 일반 세션은 45초를 넘기지 않는다.

## 3. 규칙, 생성, 점수와 종료

### 보드와 레시피

- 보드는 **6열 × 8행 = 48칸**이고 그중 **36칸에만 재료 타일**이 있다. 나머지 12칸은 비워 원본 프레임의 성긴 체크무늬 인상을 재현한다. 원본은 약 7열이지만 폭 320px에서도 44×44px 타깃을 지키기 위해 6열로 줄인다.
- 한 판은 **요리 4개**이고 각 요리는 **재료 2~3종 · 합계 5개**를 요구한다. 판당 필요한 재료는 총 **20개**, 나머지 **16개는 방해 타일**이다.
- 기준 레시피 4종(재료 라이브러리 14종에서 구성):
  | 순번 | 요리 | 요구 재료 |
  |---|---|---|
  | 1 | 베이컨 브런치 | 베이컨 ×2, 버터 ×2, 생크림 ×1 |
  | 2 | 카페 세트 | 커피 ×2, 쿠키 ×2, 티백 ×1 |
  | 3 | 팝콘 박스 | 팝콘 ×3, 컵케이크 ×2 |
  | 4 | 스테이크 플레이트 | 스테이크 ×2, 시금치 ×2, 버터 ×1 |
- **생성 순서는 레시피가 먼저다.** 4개 레시피를 확정한 뒤 요구 재료 20개를 먼저 배치하고, 그다음 방해 타일 16개를 채운다. 따라서 "필요한 재료가 보드에 없는 판"은 구조적으로 생성되지 않는다.
- **해결 가능성 불변식:** 타일은 정답 수집으로만 사라지고 오답으로는 절대 제거되지 않는다. 그러므로 라운드 시작 시 성립한 `보드의 타입별 개수 ≥ 남은 요리들의 타입별 요구 합계`는 라운드 끝까지 유지된다. 이 불변식을 `?test=1` 자동 검사로 고정한다.
- 방해 타일은 라이브러리 14종에서 뽑되, 한 타입의 총 개수가 `그 타입을 요구하는 모든 요리의 합계 + 0~2개`를 넘지 않게 한다. 같은 타입이 화면 절반에 몰리지 않도록 배치 시 3칸 이내 동일 타입 인접을 최대 2회로 제한한다.

### 입력 판정과 오답

탭한 타일의 타입을 기준으로 세 갈래로만 판정한다.

- **정답:** 현재 요리가 그 타입을 아직 요구한다 → 타일 제거, 요구 수량 -1, 점수 +20, 콤보 +1.
- **소프트 미스:** 그 타입이 **이후 요리**에는 필요하지만 지금은 아니다(또는 현재 요리의 그 타입 요구가 이미 채워졌다) → 타일은 남고 `다음 요리에서 필요해요` 안내, **-1초**, 콤보 초기화.
- **하드 미스:** 남은 어떤 요리에도 필요 없다 → 타일은 남고 `이 재료는 쓰지 않아요` 안내, **-3초**, 콤보 초기화.
- 미스로 타일을 제거하지 않는 이유는 위 불변식을 지키기 위해서다. 페널티는 시간에만 준다.
- 정답 처리 중에는 입력을 잠근다(수집 모션 200ms). 같은 타일 연타·더블탭·키 반복은 한 번만 처리한다. 미스 판정 직후에는 250ms 동안 같은 타일의 재입력만 무시해 실수 연타로 시간이 급감하지 않게 한다.

### 점수와 힌트

- 재료 1개 수집 20점, 요리 1개 완성 +100점.
- 콤보는 미스 없이 연속 수집한 횟수다. 3연속부터 `+10 × (콤보-2)`를 추가로 주고 `+50`(7연속)에서 상한이다. 미스 한 번으로 0이 된다.
- 성공 시 `floor(남은 초) × 10`을 시간 보너스로 한 번 더한다.
- **6초 동안 정답 수집이 없으면** `힌트` 버튼이 활성화된다. 사용하면 현재 요리에 필요한 타일 한 개를 1.4초 동안 색이 아닌 굵은 테두리 + 동일 심볼 배지로 표시한다. 최종 점수에서 75점을 차감하며 점수는 0 미만이 되지 않는다.
- 남은 시간, 점수, 진행 `n/4`, 요구 수량은 항상 텍스트로 함께 표시하고 색만으로 상태를 전달하지 않는다.

### 성공·실패

- **성공:** 네 번째 요리의 마지막 요구 수량이 0이 되고 서빙 연출이 끝난 시점. 최종 점수, 소요 시간, 완성 `4/4`, 미스 횟수를 표시한다.
- **실패 — 시간 종료:** 40초가 되었는데 남은 요리가 있는 경우. `시간 안에 네 접시를 못 채웠어요`와 완성한 요리 수, 마지막 요리의 잔여 요구를 보여준다.
- 시간 만료와 마지막 수집이 같은 프레임에 경합하면 이미 시작된 유효 입력의 수집·요리 완성·성공 판정을 먼저 끝내고 타이머 종료를 무시한다.
- 종료는 `finishOnce(result)` 가드로 한 번만 실행한다. 실패는 즉시 재도전 가능하며 강제 대기·구매·스토어 CTA는 넣지 않는다.

## 4. 화면과 정보 구조

세로형 `max-width: 480px`, `min-height: 100dvh` 스테이지를 기준으로 위에서 아래로 구성한다.

1. **상단 HUD:** `DISH COLLECT` 제목, 남은 시간 `40`, 점수, 진행 `0/4`, 음소거 버튼.
2. **접시 영역:** 하늘 배경 위에 큰 원형 접시. 접시 위에는 이미 수집한 재료가 실제로 쌓여 요리가 완성되어 가는 것이 보인다. 접시 아래 요구 카드에 `베이컨 2 · 버터 2 · 생크림 1`처럼 남은 수량을 아이콘+숫자로 표시하고, 0이 된 항목은 체크 표시와 함께 흐리게 만든다.
3. **다음 요리 미리보기:** 접시 우측 상단에 작은 썸네일과 `다음: 카페 세트`. 소프트 미스 판단의 근거를 화면에 준다.
4. **재료 보드:** 연한 체크무늬 6×8 격자. 각 칸은 최소 44×44px이고 빈 칸은 조작 대상이 아니다.
5. **상태 안내:** 튜토리얼, 콤보, 미스 사유, 힌트를 한 줄로 표시한다. live region을 공유하되 타이머를 매초 읽지 않는다.
6. **결과 레이어:** 완성된 네 접시가 함께 보이도록 상단을 일부 남긴 모달 카드. 결과 제목, 점수·시간·진행·미스, `다시 만들기`, `다른 데모 보기` 순서다.

## 5. 입력과 상호작용

- **마우스·터치:** 재료 타일 전체가 버튼이다. `touch-action: manipulation`을 적용하고 hover는 부가 강조에만 쓴다.
- **키보드:** 보드는 roving tabindex 격자다. 방향키로 인접한 **남아 있는** 타일로 이동하고(빈 칸·수집된 칸은 건너뛴다), `Enter`/`Space`로 수집한다. `Tab`은 보드 전체를 한 정거장으로 취급해 HUD·힌트·음소거·결과 버튼으로 넘어간다.
- `H`는 힌트가 활성일 때 사용, `M`은 음소거, 결과 화면의 `R`은 재시작이다. 버튼·링크에 포커스가 있을 때 전역 단축키는 중복 실행하지 않는다.
- 포인터·터치·키보드는 모두 `collect(tileId)` 하나로 진입한다. 입력 방식에 따라 점수·시간·판정이 달라지지 않는다.
- 수집된 타일에 포커스가 있었다면 같은 행에서 가장 가까운 남은 타일, 없으면 논리 순서상 다음 남은 타일로 옮긴다. 요리가 교체되면 포커스는 유지하고 요구 카드 변경만 알린다. 보드 조작이 끝나면 결과 제목으로 이동한다.

## 6. 상태와 데이터 모델

```text
BOOT → READY → PLAYING ↔ COLLECTING → SERVING → PLAYING
                                          └────→ WON
              PLAYING ─────────────────────────→ LOST_TIME
WON/LOST_TIME ── replay ──→ READY
```

```js
state = {
  phase: 'ready' | 'playing' | 'collecting' | 'serving' | 'won' | 'lost-time',
  seed, runCount, startedAt, remainingMs,
  score, combo, lastCollectAt, hintUsed, missSoft, missHard,
  recipes: [{ id, nameKo, need: { [typeId]: remaining }, plated: [typeId] }],
  currentRecipe,           // 0..3
  tiles: [{ id, typeId, col, row, status: 'board' | 'collected' }],
  muted, reducedMotion, focusTileId
}
```

- `INGREDIENT_LIBRARY`는 14개의 `{id, nameKo, silhouette, palette, pattern}`이다: 베이컨, 스테이크, 다짐육 패티, 팝콘, 시금치, 커피잔, 홍차잔, 티백, 생크림 볼, 컵케이크, 버터, 초코쿠키, 요거트, 테이크아웃 컵.
- `createRound(seed)`는 레시피 4개 선정 → 요구 타일 20개 생성 → 방해 타일 16개 생성 → Fisher–Yates 셔플 → 48칸 중 36칸 배치 순서로 동작한다. 같은 `?seed=`는 같은 레시피·타일·좌표를 만든다.
- 파생값인 남은 타일 수, 진행률, 현재 요구 합계는 저장하지 않고 `tiles`와 `recipes`에서 계산한다.
- 순수 함수는 `createRound(seed)`, `classifyTap(typeId)`, `collect(tileId)`, `advanceRecipe()`, `calculateScore(now)`, `getOutcome(now)`로 분리한다.
- 타이머는 `performance.now()` 기준이다. 문서가 숨겨지면 일시정지하고 복귀 시 `계속하기` 안내 후 재개해 백그라운드 탭 때문에 실패하지 않게 한다.
- 렌더링은 단일 `render(state)` 경로를 쓴다. 접시에 쌓인 재료는 `plated` 배열에서만 그린다.

## 7. 오리지널·절차형 에셋

- 재료 14종은 자체 인라인 SVG로 제작한다. 각 아이콘은 색뿐 아니라 외곽 실루엣, 그릇 유무, 내부 줄무늬·점무늬가 서로 다르다. 특히 혼동 위험이 큰 조합(스테이크/베이컨/패티, 커피/홍차/요거트)은 실루엣과 무늬를 우선 분리하고 색은 보조 신호로만 쓴다.
- 요리 4종은 별도 일러스트가 아니라 **수집된 재료 SVG를 접시 위에 규칙적으로 배치해 조립**한다. 아트 물량을 늘리지 않으면서 "내가 모은 것이 곧 요리"라는 피드백을 준다.
- 하늘 배경, 구름, 원형 접시, 체크무늬 보드, 요구 카드, 다음 요리 썸네일은 CSS gradient·pseudo-element와 인라인 SVG로 만든다.
- 금색 수집 궤적은 이미지 없이 3~5개의 작은 SVG 원을 베지어 경로로 이동시키는 절차 생성이다. 파티클 총량은 동시에 12개를 넘지 않는다.
- 시스템 폰트와 Web Audio 합성음을 사용해 이미지·폰트·음원·CDN·외부 라이브러리 요청을 **0건**으로 만든다. 무료 에셋을 쓰게 되면 CC0/OFL 계열만 사용하고 출처를 `ASSETS.md`에 남긴다.

## 8. 모션과 오디오

- 수집 궤적 200ms, 접시 적재 튕김 140ms, 요구 카드 체크 160ms, 요리 교체 320ms, 결과 카드 220ms를 기준으로 한다. `transform`과 `opacity` 위주로 구현한다.
- 미스는 화면 전체 흔들기 대신 해당 타일의 6px 좌우 흔들림(160ms), 시간 표시의 짧은 붉은 펄스, 원인 문구로 알린다.
- 첫 요구 재료 강조는 최대 두 번만 맥동하고 첫 입력 즉시 멈춘다. 수동 힌트도 1.4초 뒤 자동 해제된다.
- Web Audio API는 첫 사용자 입력 뒤에만 시작하며 수집, 요리 완성, 미스, 성공/실패의 짧은 합성음만 낸다. 배경음과 자동 재생은 없다.
- `prefers-reduced-motion: reduce`에서는 궤적·맥동·흔들림·파티클을 제거하고 0~40ms 내 정적 상태 변화(타일 즉시 제거, 요구 수량 즉시 갱신)로 바꾼다. 판정 순서와 시간 페널티는 동일하다.

## 9. 접근성

- 문서 언어는 `ko`이고, 재료 타일은 네이티브 `<button>`이다. 접근성 이름은 `베이컨, 3행 2열, 지금 필요함`처럼 종류·논리 위치·현재 필요 여부를 포함한다. 필요 여부를 이름에 넣어 색 강조에 의존하지 않게 한다.
- 요구 카드는 `베이컨 2개 남음, 버터 2개 남음, 생크림 1개 남음`처럼 텍스트로 읽히고, 수집·요리 완성·미스 사유·힌트는 `aria-live="polite"`로 알린다.
- 타이머는 화면에 계속 표시하되 낭독은 10초·5초에만 한다. 시간 제한이 어려운 사용자를 위해 첫 화면의 `여유 모드`를 선택하면 제한 시간과 미스 시간 페널티를 없애고 기록에 `연습`으로 표시한다.
- 포커스 링과 비텍스트 경계는 배경 대비 3:1 이상, 일반 텍스트는 WCAG AA 대비를 목표로 한다. 체크무늬 배경 위에서도 아이콘 실루엣이 3:1 이상 구분되어야 한다.
- 200% 확대, 강제 색상, 음소거, 축소 동작에서도 모든 타일·요구 카드·결과 행동에 접근 가능해야 한다.

## 10. 반응형 동작

- `viewport-fit=cover`, `min-height: 100dvh`, safe-area inset을 적용한다. 앱 콘텐츠 폭은 `min(100% - 24px, 480px)`로 제한한다.
- **320~480px 세로:** 6열×8행을 유지하고 각 칸은 최소 44px다. 320px에서는 격자 간격을 2px로 줄이고 `clamp()`로 아이콘 크기를 조절한다.
- **높이 650px 미만:** 접시 지름과 하늘 영역을 축소하고 HUD를 2행으로 압축한다. 요구 카드와 보드를 우선 노출하며 필요한 경우 짧은 세로 스크롤을 허용한다.
- **가로·태블릿:** 접시·요구 카드·다음 요리를 왼쪽, 보드를 오른쪽에 둔 2열 레이아웃으로 전환한다. DOM 순서, 격자 좌표, 상태는 바꾸지 않는다.
- 리사이즈·방향 전환 시 남은 시간, 점수, 요구 수량, 접시 적재, 포커스 타일을 보존한다.
- 320×568, 390×844, 844×390, 768×1024, 1440×900에서 가로 스크롤, 겹친 필수 조작, 가려진 결과 버튼이 없어야 한다.

## 11. 독립 파일 구현 개요

개발 경로는 `games/dish-collect/`이며 공유 모듈이나 빌드 과정 없이 세 파일로 독립 실행한다.

### `index.html`

- 한국어 메타데이터와 viewport 설정, 의미 있는 `main`, HUD, 접시·요구 카드·다음 요리, 6×8 보드, 상태 안내, live region, 힌트·음소거 버튼, 결과 `dialog` 또는 동등한 접근성 모달을 포함한다.
- `style.css`, `script.js`만 상대 경로로 연결하고 `noscript` 안내를 제공한다.

### `style.css`

- 색·간격·명암 CSS 변수, 모바일 우선 레이아웃, 체크무늬 격자, 44px 타깃, 요구 카드·접시·포커스 스타일을 정의한다.
- 저높이·가로·태블릿 미디어 쿼리, safe area, `prefers-reduced-motion`, `prefers-contrast`, `forced-colors` 대체 스타일을 포함한다.

### `script.js`

- 재료 메타데이터와 SVG 생성기, seeded PRNG/Fisher–Yates, 레시피 우선 라운드 생성, 탭 분류·수집·요리 교체·점수·종료의 순수 상태 전이, 단일 렌더러를 구현한다.
- Pointer/click, 격자 키보드 탐색, visibility, resize, 오디오, 모달 포커스, 재시작을 한 상태 객체에 연결한다.
- URL `?seed=`로 판을 재현하고 `?test=1`에서 생성 불변식(요구 20개 선배치, 타입별 공급 ≥ 잔여 요구, 44px 비중첩)과 핵심 판정의 console assertion을 실행한다.

`games/dish-collect/index.html`을 `file://`로 직접 열어도 네트워크 요청이나 CORS 오류 없이 한 판 전체, 결과, 재시작이 동작해야 한다. 루트 CTA는 `../../index.html`을 가리키되 대상이 없어도 게임 자체는 정상 동작한다.

## 12. 인수 시나리오

1. **초기 생성:** Given 고정 seed, When 페이지가 열리면, Then 48칸 중 36칸에 타일이 놓이고 요구 재료 20개가 모두 보드에 존재하며 모든 타일이 44×44px 이상이다.
2. **정답 수집:** Given 현재 요리가 베이컨을 2개 요구할 때, When 보드의 베이컨을 한 번 탭하면, Then 타일이 한 번만 제거되고 요구가 1로 줄며 점수가 20점만 오른다.
3. **소프트 미스:** Given 버터가 현재 요리에는 필요 없지만 4번째 요리에 필요할 때, When 버터를 탭하면, Then 타일은 보드에 남고 시간이 1초만 줄며 `다음 요리에서 필요해요`가 안내된다.
4. **하드 미스:** Given 남은 어떤 요리도 요구하지 않는 요거트를 탭하면, Then 타일은 남고 시간이 3초 줄며 콤보가 0이 된다.
5. **요리 교체:** Given 현재 요리의 마지막 요구 재료를 수집하면, Then 완성 연출 후 진행이 1 증가하고 다음 요리 요구 카드로 교체되며 100점이 한 번만 더해진다.
6. **해결 가능성:** Given 임의 seed로 하드 미스를 반복해도, Then 타일은 제거되지 않으므로 남은 모든 요리를 완성할 재료가 항상 보드에 남아 있다.
7. **시간 경합:** Given 마지막 재료 탭과 40초 만료가 같은 프레임에 예약될 때, When 탭 처리가 먼저 시작됐으면, Then 성공을 확정하고 시간 실패가 덮어쓰지 않는다.
8. **힌트:** Given 6초 동안 정답 수집이 없을 때, When 힌트를 실행하면, Then 현재 요리에 필요한 타일 하나가 1.4초간 색 이외의 테두리·심볼로 표시되고 최종 점수에서 75점만 차감된다.
9. **성공·재시작:** Given 네 번째 요리를 완성하면, Then 점수·시간·`4/4`·미스 횟수가 표시되고, When 다시 만들기를 누르면 새 seed의 0점·40초·첫 요리 상태가 된다.
10. **키보드·보조 설정:** Given 마우스와 소리 없이 축소 동작·여유 모드를 사용해도, When 방향키와 Enter/Space만 사용하면, Then 네 요리를 모두 완성하고 결과를 이해할 수 있다.
11. **독립 실행·반응형:** Given 네트워크 차단과 각 기준 뷰포트, When 로컬 파일로 플레이·회전·재시작하면, Then 외부 요청·콘솔 오류·상태 초기화·가려진 조작이 없다.

## 14. 일정·견적·생산성 근거

- **분류:** Type A — 탭 매칭 / 구현 복잡도 medium. 조사 확신도는 `medium`(수집형 판정 정정 건)이다.
- **세부 투입:** 로직·상태·입력 3인일(레시피 우선 생성, 3분기 탭 판정, 요리 교체·타이머·콤보·힌트, 격자 키보드), 오리지널 아트/UI 2.5인일(재료 SVG 14종, 접시 조립 렌더링, 체크 보드·요구 카드, 반응형·모션·합성음), QA·튜닝 1.5인일(모바일·접근성·오프라인·다중 seed·난이도)로 약 **7인일**이다. Type A 3종 중 아트 물량이 가장 크다(아이콘 14종 + 접시 조립).
- **고객 안내 견적:** **₩5.5M~₩6.5M(VAT 별도)** — Type A 밴드(₩4.5M~6.5M)의 상단. 단일 레벨, 한국어 UI, 내부 QA, 승인 및 수정 1회를 포함한 계획 범위다.
- **타이틀당 기간:** **6~7영업일**(Type A 밴드 5~7일의 상단). 공용 셸을 이 타이틀에서 처음 구축하면 프로젝트 공통 공수 2영업일을 별도 배정한다.
- **4주 최대 수량:** 선임 HTML5 개발 1인 + UI/아트 0.5인 + QA 0.5인의 1트랙은 동급 Type A **3종**, 2트랙은 **6~7종**이 상한이다. 단 이 타이틀이 포함되면 아트 0.5인이 병목이므로 1트랙 3종 중 아이콘 물량이 큰 타이틀은 1종까지만 묶는다.
- **핵심 리스크:** ① 체크무늬 배경 위 유사 재료(스테이크/베이컨/패티, 커피/홍차)의 판별성, ② 오답 처리 방식이 해결 가능성을 깨는 것, ③ 40초 안에 20회 수집이 과한 난이도가 되는 것. 완화는 실루엣 우선 아이콘 설계, **미스 시 타일 비제거 원칙**, seed 100회 자동 검증과 실제 모바일 플레이테스트로 요구 수량(5개)·제한 시간(40초)을 조정하는 것이다.
- **별도 범위:** 브랜드 일러스트, 전문 녹음 음원, 광고 SDK·분석 연동, 추가 레벨·레시피 팩, 다국어, 서버 저장, 앱 패키징은 포함하지 않는다.
