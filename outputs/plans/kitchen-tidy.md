# 키친 타이디(Kitchen Tidy) 제작 계획

## 1. 기획 기준과 플레이어 약속

- **관찰 근거:** 원본 `01:52`와 `02:20`의 세 번째 패널에서 싱크·가스레인지가 있는 주방 바닥에 팬, 그릇, 주걱, 소형 가전 등의 조리도구가 흩어져 있고 시간이 지나며 개수가 줄어드는 장면을 확인했다.
- **확정된 핵심:** 바닥의 조리도구를 탭해 같은 종류끼리 매칭·제거하고 전부 치우면 완료하는 세로형 미니게임이다.
- **구현 가정:** 영상 프레임만으로는 2개/3개 매칭, 보관 슬롯, 점수와 실패 조건을 판별할 수 없다. 개발 기준은 **동일 도구 3개 매칭**, **7칸 정리 바구니**, **35초 제한**으로 고정한다. 이는 원작 재현을 주장하는 규칙이 아니라 20~45초 플레이를 위한 독자 설계다.
- **한 줄 약속:** 어질러진 주방에서 같은 조리도구 세 개를 빠르게 찾아, 바구니가 넘치기 전에 모두 정리한다.
- **톤:** 포근한 아침 주방, 부드러운 파스텔 색, 짧고 명확한 정리 쾌감. 원본 로고·캐릭터·화면 캡처·추출 음원은 사용하지 않는다.

## 2. 1라운드 코어 루프(약 25~40초)

1. **도입 0~3초:** 24개 조리도구가 주방 바닥에 흩어지고, 해결 가능한 첫 세트 3개가 최대 두 번 은은하게 강조된다. `같은 도구 3개를 모아보세요` 안내를 표시한다.
2. **탐색·수집 3~30초:** 도구를 탭하면 하단 7칸 정리 바구니의 다음 빈칸으로 이동한다. 같은 종류가 3개 모이면 자동으로 사라지고 정리 진행 `1/8`과 점수가 오른다.
3. **압박 관리:** 서로 다른 도구를 무계획하게 담으면 바구니가 찬다. 플레이어는 바닥의 전체 구성을 보고 완성 가능한 세트를 먼저 골라야 한다.
4. **종료 30~40초:** 8세트를 모두 제거하면 성공한다. 트리플 처리 후 바구니가 7칸으로 남거나 35초가 끝나면 실패한다. 결과에서 즉시 다시 하기와 비상업용 `다른 데모 보기`를 제공한다.

첫 판은 튜토리얼 세트를 쉽게 찾도록 배치하고, 재시작부터는 고정 규칙 안에서 새 시드로 섞는다. 결과 확인을 포함한 일반 세션은 45초를 넘기지 않는다.

## 3. 규칙, 생성, 점수와 종료

### 보드와 매칭

- 한 판은 조리도구 **8종 × 각 3개 = 24개**다. 12종 라이브러리에서 8종을 뽑아 4열×6행 논리 앵커에 배치하고, 각 버튼에 제한된 위치 흔들림과 회전을 줘 흩어진 느낌을 만든다.
- 시각적 겹침은 그림자·회전으로만 표현한다. 실제 버튼의 클릭 영역은 서로 겹치지 않으며 최소 44×44px다. 어떤 도구도 다른 도구에 가려 선택 불가능해지지 않는다.
- 도구를 선택하면 바닥에서는 즉시 비활성화하고 바구니에 넣는다. 같은 종류 3개가 있으면 세 개를 제거한다.
- **판정 순서:** 입력 잠금 → 도구 이동 → 트리플 탐색·제거 → 성공 확인 → 바구니 초과 확인 → 입력 해제. 일곱 번째 도구가 트리플을 완성하면 실패하지 않는다.
- 이동·제거 중 같은 버튼을 연타해도 한 번만 처리한다. 결과가 확정된 뒤의 입력과 타이머 틱은 무시한다.
- 정확히 세 개씩 생성하므로 세트 자체는 항상 존재한다. 첫 안내 세트 3개는 서로 다른 화면 사분면에 두고 다른 아이콘과 명확히 구분되게 한다.

### 점수와 힌트

- 트리플 1세트당 100점.
- 이전 트리플 완료 후 4초 안에 다음 트리플을 만들면 `+25 × 연속 단계` 보너스를 주고, 연속 단계는 3(+75)에서 상한이다.
- 성공 시 `floor(남은 초) × 10`을 시간 보너스로 한 번 더한다.
- 7초 동안 트리플이 없으면 `힌트` 버튼이 활성화된다. 사용하면 바구니에 든 수와 바닥에 남은 수를 합쳐 정확히 3개인 한 종류를 골라, 바구니 아이콘과 아직 필요한 바닥 도구를 1.2초간 테두리·동일 심볼로 강조한다. 최종 점수에서 100점을 차감하며 점수는 0 미만이 되지 않는다.
- 진행률, 바구니 수, 점수, 남은 시간은 항상 텍스트로 함께 표시하며 색만으로 상태를 전달하지 않는다.

### 성공·실패

- **성공:** 바닥과 바구니의 도구가 모두 0개이고 해결 애니메이션이 끝난 시점. 최종 점수, 소요 시간, 정리한 세트 `8/8`을 표시한다.
- **실패 1 — 바구니 가득 참:** 트리플 제거를 먼저 처리한 뒤 바구니에 7개가 남은 경우. `바구니가 가득 찼어요`와 현재 구성 아이콘을 보여준다.
- **실패 2 — 시간 종료:** 35초가 되었는데 바닥 또는 바구니에 도구가 남아 있는 경우. `시간 안에 다 치우지 못했어요`와 정리한 세트 수를 보여준다.
- 마지막 트리플 입력이 시간 만료와 같은 프레임에 경합하면 이미 시작된 유효 입력의 이동·트리플·성공 판정을 먼저 완료하고 타이머 종료를 무시한다.
- 실패는 즉시 재도전 가능하며 강제 대기·구매·스토어 CTA를 넣지 않는다.

## 4. 화면과 정보 구조

세로형 `max-width: 480px`, `min-height: 100dvh` 스테이지를 기준으로 위에서 아래로 구성한다.

1. **상단 HUD:** `KITCHEN TIDY` 제목, 남은 시간 `35`, 점수, 정리 진행 `0/8`, 음소거 버튼.
2. **주방 장면:** 창문·싱크·가스레인지·수납장을 배경으로 두고, 하단 바닥 영역에 24개 조리도구 버튼을 흩어 배치한다. 배경 가구는 조작 요소와 형태·명도가 겹치지 않게 낮은 대비로 처리한다.
3. **상태 안내:** 최초 튜토리얼, 콤보, 힌트와 실패 원인을 한 줄로 표시한다. 실시간 변화는 시각 문구와 별도의 live region을 공유하되 타이머를 매초 읽지는 않는다.
4. **정리 바구니:** 7칸 슬롯, `바구니 0/7` 라벨, 들어온 도구의 작은 아이콘. safe-area 위에 고정된 시각 영역으로 두되 게임 보드를 가리지 않는다.
5. **결과 레이어:** 정리 전후가 비교되도록 장면을 일부 남긴 모달 카드. 결과 제목, 점수·시간·진행, `다시 정리하기`, `다른 데모 보기` 순서다.

## 5. 입력과 상호작용

- **마우스·터치:** 조리도구 전체 버튼을 클릭/탭한다. `touch-action: manipulation`을 적용하고 hover는 부가 강조에만 쓴다.
- **키보드:** `Tab`/`Shift+Tab`으로 남은 도구와 HUD 버튼을 순회하고 `Enter`/`Space`로 선택한다. 도구 영역의 방향키는 각 버튼 중심 좌표를 기준으로 해당 방향에서 가장 가까운 남은 도구로 이동한다.
- `H`는 힌트가 활성일 때 사용, `M`은 음소거, 결과 화면의 `R`은 재시작이다. 버튼 또는 링크에 텍스트 입력 포커스가 있을 때 전역 단축키는 중복 실행하지 않는다.
- 포인터·터치·키보드는 모두 `selectTool(id)` 하나로 진입한다. 입력 방식에 따라 점수·시간·판정이 달라지지 않는다.
- 제거된 도구에 포커스가 있었다면 같은 종류의 다음 도구, 없으면 논리 순서상 다음 남은 도구로 옮긴다. 보드가 비면 결과 제목으로 이동한다.

## 6. 상태와 데이터 모델

```text
BOOT → READY → PLAYING ↔ RESOLVING → WON
                          ├─────────→ LOST_FULL
                          └─────────→ LOST_TIME
WON/LOST_* ── replay ──→ READY
```

```js
state = {
  phase: 'ready' | 'playing' | 'resolving' | 'won' | 'lost-full' | 'lost-time',
  seed, runCount, startedAt, remainingMs,
  score, comboLevel, lastMatchAt, hintUsed, lastProgressAt,
  tools: [{ id, typeId, anchor, x, y, angle, status: 'floor' | 'basket' | 'cleared' }],
  basket: [toolId], // 최대 7
  clearedSets,     // 0..8
  muted, reducedMotion
}
```

- `TOOL_LIBRARY`는 12개의 `{id, nameKo, shape, palette, pattern}`을 가진다. 라운드에는 서로 구별되는 8종만 고른다.
- `createRound(seed)`는 종류 선정, 각 3개 복제, Fisher–Yates 셔플, 앵커 배치와 제한된 회전값을 결정한다. 같은 `?seed=`는 같은 종류·위치·각도를 만든다.
- 파생값인 바닥 개수, 바구니 개수, 남은 세트는 저장하지 않고 `tools`와 `basket`에서 계산한다.
- 주요 순수 함수는 `createRound(seed)`, `selectTool(id)`, `findTriple(basket)`, `resolveTriple(typeId)`, `calculateScore(now)`, `getOutcome(now)`로 분리한다.
- 타이머는 `performance.now()` 기준으로 계산한다. 문서가 숨겨진 동안 일시정지하고 복귀 시 `계속하기` 안내 후 재개해 백그라운드 탭 때문에 실패하지 않게 한다.
- 렌더링은 단일 `render(state)` 경로를 사용하고, 종료는 `finishOnce(result)` 가드로 한 번만 실행한다.

## 7. 오리지널·절차형 에셋

- 조리도구 12종은 팬, 냄비, 주걱, 거품기, 그릇, 머그, 주전자, 토스터, 와플팬, 도마, 절구, 오븐 장갑으로 구성하고 자체 인라인 SVG로 제작한다.
- 각 아이콘은 색뿐 아니라 외곽 실루엣, 손잡이 방향, 내부 줄무늬·점무늬가 다르다. 같은 종류 세 개는 동일한 핵심 실루엣을 유지하되 3° 이내의 장식 회전만 다르게 한다.
- 주방 배경의 벽, 창문, 싱크, 수납장, 타일 바닥, 7칸 바구니는 CSS gradient·pseudo-element와 인라인 SVG로 만든다.
- 먼지 점, 비눗방울, 체크·별 파티클도 CSS/SVG 절차 생성으로 제한한다. 시스템 폰트와 Web Audio 합성을 사용해 이미지·폰트·음원·CDN·외부 라이브러리 요청은 0건으로 한다.
- 참고 영상은 메커니즘 확인에만 쓰며 원본 로고, 캐릭터, UI 캡처, 추출 에셋·사운드를 복제하지 않는다.

## 8. 모션과 오디오

- 도구가 바구니로 이동하는 모션 180ms, 트리플 축소와 비눗방울 220ms, 진행 체크 160ms, 결과 카드 220ms를 기준으로 한다. `transform`과 `opacity` 위주로 구현한다.
- 처음 제시하는 3개 힌트는 최대 두 번만 맥동하고 첫 입력 즉시 멈춘다. 수동 힌트도 1.2초 뒤 자동 해제된다.
- 실패 시 화면 전체 흔들기 대신 바구니 테두리, 원인 문구와 낮은 단음으로 알린다. 성공은 정돈된 바닥과 3음 상승음으로 전달한다.
- Web Audio API는 첫 사용자 입력 뒤에만 시작하며 탭, 트리플, 성공, 실패의 짧은 합성음만 낸다. 배경음과 자동 재생은 없다.
- `prefers-reduced-motion: reduce`에서는 이동, 회전, 맥동, 파티클을 제거하고 0~40ms 내 정적 슬롯·체크 상태로 바꾼다. 판정 순서는 동일하다.

## 9. 접근성

- 문서 언어는 `ko`이고, 도구는 네이티브 `<button>`으로 구현한다. 접근성 이름은 `프라이팬, 바닥 2행 3열`처럼 종류와 논리 위치를 포함한다.
- 바구니는 조작 대상이 아니며 `프라이팬 2개, 머그 1개, 총 3/7`처럼 텍스트 요약을 제공한다. 트리플 완료, 힌트, 실패, 성공은 `aria-live="polite"`로 알린다.
- 타이머는 화면에 계속 표시하되 화면 낭독에는 10초, 5초만 알린다. 시간 제한이 어려운 사용자를 위해 첫 화면의 `여유 모드`를 선택하면 제한 시간을 없애고 기록에는 `연습`으로 표시한다.
- 포커스 링과 비텍스트 경계는 배경 대비 3:1 이상, 일반 텍스트는 WCAG AA 대비를 목표로 한다. 색, 위치, 소리 하나에만 정답·선택·종료 정보를 의존하지 않는다.
- 200% 확대, 강제 색상, 음소거, 축소 동작에서도 모든 도구·바구니·결과 행동에 접근 가능해야 한다.

## 10. 반응형 동작

- `viewport-fit=cover`, `min-height: 100dvh`, safe-area inset을 적용한다. 앱 콘텐츠 폭은 `min(100% - 24px, 480px)`로 제한한다.
- **320~480px 세로:** 4×6 논리 앵커를 유지하고 각 버튼은 최소 44px다. `clamp()`로 장면 여백과 아이콘 크기를 조절한다.
- **높이 650px 미만:** 상부 장식과 가구 높이를 줄이고 HUD를 2행으로 압축한다. 바닥과 바구니는 우선 노출하며 필요한 경우 문서의 짧은 세로 스크롤을 허용한다.
- **가로·태블릿:** 주방 장면을 왼쪽, HUD·안내·바구니를 오른쪽에 둔 2열 레이아웃으로 전환한다. DOM 순서와 논리 앵커, 상태는 바꾸지 않는다.
- 리사이즈·방향 전환 시 normalized 좌표에서 위치를 다시 계산하고 남은 시간, 점수, 바구니, 포커스를 보존한다.
- 320×568, 390×844, 844×390, 768×1024, 1440×900에서 가로 스크롤, 겹친 필수 조작, 가려진 결과 버튼이 없어야 한다.

## 11. 독립 파일 구현 개요

개발 경로는 `games/kitchen-tidy/`이며 공유 모듈이나 빌드 과정 없이 세 파일로 독립 실행한다.

### `index.html`

- 한국어 메타데이터와 viewport 설정, 의미 있는 `main`, HUD, 상태 안내, 도구 레이어, 7칸 바구니, live region, 힌트·음소거 버튼, 결과 `dialog` 또는 동등한 접근성 모달을 포함한다.
- `style.css`, `script.js`만 상대 경로로 연결하고 `noscript` 안내를 제공한다.

### `style.css`

- 색·간격·명암 CSS 변수, 모바일 우선 주방 레이아웃, 4×6 앵커, 44px 타깃, 바구니와 상태·포커스 스타일을 정의한다.
- 저높이·가로·태블릿 미디어 쿼리, safe area, `prefers-reduced-motion`, `prefers-contrast`, `forced-colors` 대체 스타일을 포함한다.

### `script.js`

- 도구 메타데이터와 SVG 생성기, seeded PRNG/Fisher–Yates, 라운드 생성, 선택·바구니·트리플·점수·종료의 순수 상태 전이, 단일 렌더러를 구현한다.
- Pointer/click, 키보드 공간 탐색, visibility, resize, 오디오, 모달 포커스, 재시작을 한 상태 객체에 연결한다.
- URL `?seed=`로 판을 재현하고 `?test=1`에서 생성 불변식과 핵심 판정의 console assertion을 실행한다.

`games/kitchen-tidy/index.html`을 `file://`로 직접 열어도 네트워크 요청이나 CORS 오류 없이 한 판 전체, 결과, 재시작이 동작해야 한다. 루트 CTA는 `../../index.html`을 가리키되 대상이 없어도 게임 자체는 정상 동작한다.

## 12. 인수 시나리오

1. **초기 생성:** Given 고정 seed, When 페이지가 열리면, Then 서로 다른 8종이 각 3개씩 총 24개 생성되고 모든 버튼이 44×44px 이상이며 첫 안전 세트가 안내된다.
2. **일반 수집:** Given 플레이 중, When 바닥 도구를 한 번 선택하면, Then 해당 도구는 정확히 한 번만 바구니로 이동하고 바닥에서 다시 선택되지 않는다.
3. **트리플:** Given 같은 종류 2개가 바구니에 있을 때, When 세 번째를 넣으면, Then 그 세 개가 먼저 제거되고 진행이 1 증가하며 100점 이상이 한 번만 더해진다.
4. **경계 판정:** Given 바구니에 6개가 있고 그중 같은 종류 2개가 있을 때, When 일곱 번째 동일 도구를 넣으면, Then 트리플을 먼저 지우고 `lost-full`로 가지 않는다.
5. **바구니 실패:** Given 바구니에 서로 트리플이 되지 않는 6개가 있을 때, When 일곱 번째 비매칭 도구를 넣으면, Then 입력이 잠기고 `바구니가 가득 찼어요` 결과가 한 번 열린다.
6. **시간 경합:** Given 마지막 세트 선택과 35초 만료가 같은 프레임에 예약될 때, When 선택 처리가 먼저 시작됐으면, Then 트리플·성공을 확정하고 시간 실패가 덮어쓰지 않는다.
7. **힌트:** Given 7초 동안 트리플이 없을 때, When 힌트를 실행하면, Then 완성 가능한 한 종류의 현재 바구니 아이콘과 필요한 바닥 도구가 1.2초간 색 이외의 테두리·동일 심볼로 표시되고 최종 점수에서 100점만 차감된다.
8. **성공·재시작:** Given 마지막 트리플을 제거했을 때, Then 점수·시간·`8/8` 결과가 표시되고, When 다시 정리하기를 누르면 새 seed의 0점·빈 바구니·35초 상태가 된다.
9. **키보드·보조 설정:** Given 마우스와 소리 없이 축소 동작·여유 모드를 사용해도, When Tab/방향키와 Enter/Space만 사용하면, Then 모든 도구를 선택해 라운드를 완료하고 결과를 이해할 수 있다.
10. **독립 실행·반응형:** Given 네트워크 차단과 각 기준 뷰포트, When 로컬 파일로 플레이·회전·재시작하면, Then 외부 요청·콘솔 오류·상태 초기화·가려진 조작이 없다.

## 14. 일정·견적·생산성 근거

- **분류:** Type A — 탭 매칭 / 구현 복잡도 medium.
- **세부 투입:** 로직·상태·입력 3일(시드 배치, 7칸 바구니, 트리플·타이머·힌트, 동시성·키보드), 오리지널 아트/UI 2일(도구 SVG 12종, 주방 장면, 반응형·모션·합성음), QA·튜닝 1.5일(모바일·접근성·오프라인·다중 seed·난이도)로 약 **6.5인일**이다.
- **고객 안내 견적:** **₩4.5M~₩6.5M(VAT 별도)**. 단일 레벨, 한국어 UI, 내부 QA, 승인 및 수정 1회를 포함한 계획 범위다.
- **타이틀당 기간:** **5~7영업일**. 공용 셸을 이 타이틀에서 처음 구축하면 프로젝트 공통 공수 2영업일을 별도 배정한다.
- **4주 최대 수량:** 선임 HTML5 개발 1인 + UI/아트 0.5인 + QA 0.5인의 1트랙은 동급 Type A **3종**, 2트랙은 **6~7종**이 상한이다.
