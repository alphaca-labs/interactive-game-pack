# Winter Pantry 제작 계획

> **구현 경로는 `games/game-04/` 다.** 이 문서가 아니라 `games/game-04/game.json` 이 경로·슬러그·견적의 근거이며, 목록·링크는 `games/*/game.json` 을 글롭해 만든다(검증: `scripts/check-hub.mjs`). 아래 본문의 경로는 실제 디렉터리에 맞춰 갱신했다.

## 1. 한 줄 약속과 범위

눈 내리는 산장 식료품 저장고에서 제한 시간 안에 주문 카드가 요구하는 재료 5개를 찾아 따뜻한 식사를 완성한다. 한 손 탭만으로 규칙을 이해하고 20~45초 안에 결과·재도전까지 경험하는 세로형 HTML5 미니게임이다.

- 근거: 참고 화면의 생존 분위기, 목표 재료 `×5`, 5열×4행 음식 그리드를 재해석한다.
- 범위: 한국어 단일 레벨, 무작위 라운드, 시작 안내, 성공/실패, 점수, 다시 하기, 데모 CTA.
- 비범위: 원본 게임의 로고·캐릭터·이미지 복제, 외부 SDK/분석, 광고 스토어 연결, 서버 저장, 추가 레벨·다국어.

## 2. 20~45초 플레이 루프

1. **준비(0~2초)**: 목표 카드에 재료 그림·이름과 `0/5`, “같은 재료 5개를 찾아요”가 보인다. 첫 입력 즉시 안내가 사라지고 타이머가 시작된다.
2. **탐색(약 15~30초)**: 5×4 선반에서 목표 재료를 탭한다. 정답은 바구니로 수집되고 목표 수와 점수가 오른다. 오답은 짧게 표시되고 시간이 줄어든다.
3. **판정(약 1초)**: 5개를 모두 찾으면 식사가 완성되고, 시간이 0이 되면 난롯불이 약해지며 실패한다.
4. **결과(3초 이상)**: 총점·찾은 개수·남은 시간을 보여 주고 `다시 찾기`와 비상업적 `다른 데모 보기` CTA를 제공한다.

정상 라운드는 최대 30초이며 시작·결과 전환을 합쳐 약 20~38초를 목표로 한다. 결과 화면은 자동으로 닫히지 않아 전체 체류 시간이 45초를 넘어도 조작권은 사용자에게 남긴다.

## 3. 찾기·개수·보드 규칙

- 보드는 항상 **5열×4행, 총 20칸**이다.
- 라운드마다 20종 재료 중 시각적으로 구분되는 1종을 목표로 뽑아 정확히 5칸에 배치한다.
- 나머지 15칸은 목표와 다른 재료 5~8종으로 구성한다. 같은 실루엣·명칭의 변형 색상은 같은 라운드에 함께 쓰지 않는다.
- Fisher–Yates 셔플로 위치를 섞고, `?seed=` 값이 있으면 동일 보드를 재현할 수 있게 한다.
- 정답 칸은 한 번만 집계하며 수집 후 체크·빈 바구니 상태로 잠긴다. 연속 탭이나 포인터 중복 이벤트로 재집계하지 않는다.
- 오답 칸은 제거하지 않고 450ms 동안 X 표식과 테두리를 표시한다. 오답 재탭도 같은 페널티를 받되 입력 잠금 중에는 중복 차감하지 않는다.
- 시작 전 보드 탭·키 입력은 해당 선택을 유효한 첫 입력으로 처리한다. 별도 시작 버튼 때문에 한 번 더 누르게 하지 않는다.

## 4. 점수·승리·실패

- 시작 시간: 30초.
- 정답: `100 × 콤보 배수`. 배수는 연속 정답마다 `1.00 → 1.25 → 1.50 → 1.75 → 2.00`으로 올라가며 2.00이 상한이다.
- 오답: 남은 시간 2초 차감, 콤보 1.00으로 초기화, 점수 50점 차감. 점수는 0 미만으로 내려가지 않는다.
- 승리: 타이머가 0이 되기 전에 목표 재료 5개를 모두 수집. 최종 점수에 `floor(남은 초) × 10` 시간 보너스를 한 번 더한다.
- 실패: 남은 시간이 0이 되었는데 수집 수가 5 미만. 실패 순간 모든 보드 입력을 잠근다.
- 동시 판정 우선순위: 정답 입력으로 5번째 재료가 집계되면 그 입력의 점수와 승리를 먼저 확정하고 이후 타이머 틱을 무시한다.
- 재도전은 새 seed·새 목표·새 배치로 모든 점수, 시간, 수집 및 포커스 상태를 초기화한다.

## 5. 장면과 레이아웃

모바일 세로 화면을 위에서 아래로 다음 네 영역으로 구성한다.

1. **산장 헤더**: 눈 덮인 창문, `WINTER PANTRY` 작은 제목, 음소거 버튼.
2. **HUD/목표 카드**: 큰 재료 아이콘·한국어 이름·`찾은 수/5`, 30초 원형 또는 막대 타이머, 점수와 콤보. 수치만이 아니라 라벨을 항상 병기한다.
3. **식료품 선반**: 나무 선반 위 5×4 버튼 그리드. 각 칸은 최소 44×44px이고 재료 실루엣, 명암, 작은 명칭 표식을 함께 사용한다.
4. **하단 장면**: 바구니 5칸과 난로 불빛. 플레이 중에는 짧은 안내를, 종료 후에는 결과 카드와 CTA를 표시한다.

결과 카드는 같은 화면 위에 모달로 겹치되 배경을 완전히 가리지 않아 장면 맥락을 유지한다. 성공은 김이 오르는 수프, 실패는 꺼져 가는 난로로 표현하고 공포·상해 표현은 사용하지 않는다.

## 6. 입력 설계

- **포인터**: `click`을 단일 확정 이벤트로 사용한다. hover는 장식일 뿐 선택에 필수 조건이 아니다.
- **터치**: 셀 전체가 44px 이상이며 `touch-action: manipulation`, 탭 지연·더블탭 확대 오작동을 줄인다. 드래그는 요구하지 않는다.
- **키보드**: 보드 진입 시 첫 미수집 칸에 포커스. 방향키는 5×4 좌표에서 상하좌우 이동하고 경계에서는 같은 행/열에 머문다. `Enter`/`Space`로 선택, `R`로 결과 화면에서 재시작, `M`으로 음소거한다.
- 결과 모달은 포커스를 제목으로 옮기고 `Tab`을 두 CTA 안에 유지한다. 닫기 없는 필수 결과 화면이므로 `Escape`는 동작하지 않으며 재시작 후 이전 포커스 위치가 아닌 첫 칸으로 보낸다.
- 포인터·터치·키보드는 모두 같은 `selectCell(id)` 경로를 사용해 규칙 차이를 없앤다.

## 7. 상태 모델

```text
BOOT → READY → PLAYING → RESOLVING → WON
                            └──────→ LOST
WON/LOST ── replay ──→ READY
```

- `BOOT`: DOM·원본 SVG 템플릿·음향 설정 준비.
- `READY`: seed 생성, 목표와 20칸 배치, `30.0s / 0점 / 0개` 초기화. 첫 유효 입력으로 `PLAYING` 전환.
- `PLAYING`: 타이머와 입력 활성. 셀별 상태는 `available | collected | wrongFeedback`이다.
- `RESOLVING`: 마지막 정답 또는 시간 만료 시 단 한 번 진입하는 원자적 판정 구간. 타이머와 입력을 즉시 중단한다.
- `WON`/`LOST`: 결과·CTA 표시, 보드 비활성화. `restart()`만 `READY`로 복귀시킨다.

핵심 데이터는 `{phase, seed, targetId, cells, found, score, streak, timeMs, muted}`로 한 객체에서 관리한다. 렌더링은 상태를 읽기만 하며 타이머는 `performance.now()` 기준 경과 시간을 계산해 백그라운드 탭의 누적 오차를 막는다. 탭이 숨겨진 동안은 게임을 일시정지하고 복귀 시 안내 후 재개한다.

## 8. 절차적·오리지널 에셋

- 20종 재료(당근, 감자, 양파, 버섯, 옥수수, 호박, 토마토, 사과, 배, 생선, 빵 등)는 원·타원·path를 조합한 자체 제작 인라인 SVG로 만든다.
- 각 재료는 색상 외에 고유 실루엣, 내부 무늬, 2~4자 한국어 이름을 가져 색각에만 의존하지 않는다.
- 산장 벽·선반·창문·눈은 CSS gradient와 pseudo-element, 난로·바구니·수프는 인라인 SVG/CSS 도형으로 제작한다.
- 원본 참고작의 로고·UI 캡처·브랜드 캐릭터·음원을 포함하지 않는다. 외부 이미지, 웹폰트, CDN, 라이브러리 요청도 없다.
- SVG 심볼은 `script.js`의 순수 데이터/생성 함수로 만들고 필요한 아이콘만 DOM에 삽입해 중복 마크업을 줄인다.

## 9. 모션과 오디오

- 정답: 220ms scale-up 후 바구니 방향으로 320ms 이동하는 복제 아이콘, 체크 표시, 약한 불빛 상승.
- 오답: 160ms 좌우 흔들림 1회와 X 표시. 성공은 700ms 김·별 입자, 실패는 500ms 불빛 감소로 끝낸다.
- Web Audio API로 정답 2음, 오답 낮은 1음, 성공 3음만 합성한다. 사용자 입력 이후에만 AudioContext를 열며 배경음은 쓰지 않는다.
- 음소거 토글은 항상 노출하고 `localStorage`에 선택을 저장한다. 저장 불가 환경에서도 게임은 정상 작동한다.
- 소리는 보조 피드백이며 모든 결과를 텍스트·도형·상태 변화로도 전달한다.

## 10. 접근성·감소된 모션

- 각 셀은 실제 `button`이며 `aria-label="{행}행 {열}열, {재료명}"`, 수집 후 `disabled`와 “수집 완료” 상태를 제공한다.
- 목표 카드와 결과 제목을 제목 구조로 연결하고, 진행 안내용 `aria-live="polite"`에는 찾은 수·오답·종료만 알린다. 매초 타이머는 읽지 않고 10초·5초만 알린다.
- 텍스트/배경 명암비 4.5:1 이상, 비텍스트 상태 경계 3:1 이상, `:focus-visible` 3px 윤곽선을 보장한다.
- 색상만으로 정오답·목표를 구분하지 않고 아이콘, 이름, 체크/X, 문구를 병용한다.
- `prefers-reduced-motion: reduce`에서는 이동·흔들림·입자·불빛 펄스를 제거한다. 즉시 체크/X와 정적 결과 카드로 같은 정보를 준다.
- OS 고대비/강제 색상 모드에서 배경 장식을 숨기고 시스템 색상의 테두리와 텍스트가 남도록 한다.

## 11. 반응형 동작

- `viewport-fit=cover`와 safe-area inset을 적용하고, 앱은 `min-height: 100dvh`를 사용한다.
- 320×568부터 데스크톱까지 가로 스크롤 없이 동작한다. 콘텐츠 폭은 `min(100% - 24px, 560px)`로 제한한다.
- 5×4 구조는 모든 크기에서 유지한다. 셀은 `clamp(44px, 15vw, 82px)` 범위, 간격과 글꼴은 `clamp()`로 조정한다.
- 높이 650px 미만에서는 장식 헤더·하단 장면을 축소하고 HUD 여백을 줄여 보드와 결과 버튼을 우선 노출한다. 필요한 경우 세로 스크롤은 허용하되 고정 CTA가 보드를 가리지 않는다.
- 가로 화면에서는 최대 폭 760px의 2열 쉘(HUD/장면, 5×4 보드)을 사용하되 DOM 순서와 키보드 좌표는 유지한다.
- 방향 전환·리사이즈 중에도 남은 시간, 점수, 배치, 현재 포커스 셀을 보존한다.

## 12. 독립 파일 구현 개요

경로는 `games/game-04/`이며 아래 3개 파일만 사용한다. 다른 게임이나 공용 파일을 import하지 않는다.

### `index.html`

- viewport·테마 메타, 의미 있는 `main`, 헤더/HUD/목표 카드, 20칸 보드 컨테이너, 바구니, 안내 live region, 결과 `dialog` 또는 접근 가능한 모달 마크업.
- 모든 버튼의 초기 라벨과 noscript 안내 포함.
- `style.css`, `script.js`를 상대 경로로만 연결한다.

### `style.css`

- 로컬 시스템 글꼴, 색/간격/그림자 CSS 변수, 산장·선반·눈·불빛의 절차적 장식.
- 5×4 그리드, 44px 타깃, 포커스·정답·오답·수집·결과 상태, safe area, 가로/저높이 미디어 쿼리.
- `prefers-reduced-motion`, `prefers-contrast`, `forced-colors` 대체 스타일과 애니메이션 키프레임.

### `script.js`

- `INGREDIENTS` 원본 데이터와 SVG 생성기, seed PRNG/Fisher–Yates, `createRound`, `selectCell`, 점수/콤보 계산, 단조 시계 타이머, 상태 전이/렌더 함수.
- click/keydown/visibility/resize 이벤트, 포커스 관리, 음소거와 Web Audio 합성, 저장소 실패 방어.
- 중복 종료를 막는 `finishOnce(result)`와 연속 탭 잠금. URL `?seed=` 재현 및 개발용 `?test=1` 순수 함수 console assertion 제공.

`index.html`을 `file://`로 직접 열어도 네트워크 요청·CORS 오류 없이 완전한 한 라운드와 재시작이 가능해야 한다.

## 13. 인수 시나리오

1. **정상 승리** — Given 새 라운드, When 오답 없이 목표 5칸을 누르면, Then `5/5`, 승리 결과, 정답 점수와 남은 시간 보너스가 한 번만 표시된다.
2. **오답 페널티** — Given 콤보가 1.50, When 비목표 칸을 누르면, Then 시간은 정확히 2초 줄고 점수는 50점 감소(최저 0), 콤보는 1.00이 되며 해당 칸은 계속 남는다.
3. **시간 실패** — Given 4개 이하를 찾은 상태, When 시간이 0이면, Then 실패 결과가 열리고 이후 보드 입력은 점수·시간을 바꾸지 않는다.
4. **경계 동시성** — Given 마지막 목표 선택과 시간 만료가 같은 프레임에 예약됨, When 선택 핸들러가 먼저 5번째를 확정하면, Then 승리는 단 한 번 기록되고 실패로 덮어쓰지 않는다.
5. **재시작** — Given 승리 또는 실패 결과, When 다시 찾기를 누르면, Then 새 배치에서 시간·점수·콤보·진행이 초기화되고 첫 보드 칸에 포커스가 간다.
6. **키보드 완주** — Given 마우스가 없음, When 방향키와 Enter/Space만 사용하면, Then 모든 20칸에 접근하고 선택하여 라운드를 끝낼 수 있다.
7. **접근성 설정** — Given 감소된 모션과 음소거, When 정답·오답·종료가 발생하면, Then 움직임·소리 없이도 체크/X, 문구, live region으로 결과를 알 수 있다.
8. **독립 실행** — Given 네트워크가 차단됨, When `games/game-04/index.html`을 직접 열면, Then 외부 요청 없이 에셋·입력·오디오 토글·재시작이 동작한다.
9. **반응형** — Given 320×568, 390×844, 844×390, 1440×900 뷰포트, When 플레이·회전·결과 표시를 수행하면, Then 가로 스크롤·가려진 필수 조작·상태 초기화가 없다.

## 14. 테스트 계획

- **규칙 단위 테스트**: 고정 seed마다 정확히 20칸/목표 5칸/비목표 15칸인지, 셔플 재현성, 콤보 상한, 0점 하한, 시간 차감, 최종 보너스를 assertion으로 확인한다.

- **입력 테스트**: Chrome/Safari에서 mouse click, iOS/Android touch emulation, 방향키/Enter/Space/R/M, 포커스 트랩과 포커스 복귀를 점검한다.
- **접근성 테스트**: 키보드 전용, VoiceOver, 200% 확대, reduced motion, forced colors, 음소거에서 정보·조작 동등성을 확인한다.
- **레이아웃/성능 테스트**: 명시한 4개 뷰포트 및 방향 전환에서 겹침과 스크롤을 확인하고, 보급형 모바일 에뮬레이션에서 애니메이션 중 긴 작업 없이 입력이 즉시 반응하는지 본다.
- **독립성 테스트**: DevTools Network를 offline으로 두고 직접 파일 실행, 404/외부 요청/console error 0건, 재시작 20회 후 타이머·이벤트 중복 0건을 확인한다.
