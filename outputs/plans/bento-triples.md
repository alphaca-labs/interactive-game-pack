# Bento Triples 제작 계획

> **이 기획서는 납품된 8종에 포함되지 않았다.** `games/` 에 대응 디렉터리가 없으므로 경로 문구를 근거로 링크를 만들지 마라 — 목록은 `games/*/game.json` 글롭이 근거다.

## 1. 콘셉트와 플레이어 약속

- **한 줄 약속:** 한눈에 보이는 도시락 메뉴를 빠르게 골라, 트레이가 넘치기 전에 같은 메뉴 3개씩 기분 좋게 정리한다.
- **근거와 범위:** 원본 프레임에서 확인되는 음식 그리드·주문 카드·하단 수집 트레이를 바탕으로 재구성한다. 보이지 않은 전환·점수 규칙은 이 프로토타입의 독자 설계다.
- **세션 목표:** 설명을 읽지 않아도 첫 3회 탭으로 규칙을 이해하고, 한 판을 25–40초(허용 범위 20–45초)에 끝낸다.
- **톤:** 밝은 도시락 가게, 또렷한 음식 실루엣, 짧고 만족스러운 정리 감각. 원본 브랜드·로고·캐릭터·캡처 이미지는 사용하지 않는다.

## 2. 20–45초 코어 루프

1. 게임이 즉시 시작되고, 첫 안전한 트리플 3개가 은은하게 강조되며 “같은 메뉴 3개를 모아보세요”가 표시된다.
2. 플레이어가 보드의 음식 타일을 탭하면 해당 타일이 아래 7칸 트레이의 다음 빈칸으로 이동한다.
3. 트레이에 같은 음식이 3개 모이면 세 타일이 사라지고 주문표가 1칸 찍히며 점수를 얻는다.
4. 빈 트레이 공간을 관리하면서 8개의 트리플을 모두 만든다.
5. 보드를 비우면 성공, 트리플 처리 후에도 트레이 7칸이 모두 차 있으면 실패한다. 결과 화면에서 즉시 다시 하기 또는 비상업용 포트폴리오 CTA를 선택한다.

## 3. 규칙, 점수, 성공·실패

### 보드와 진행

- 한 판은 24개 타일, 즉 무작위로 고른 음식 8종을 각 3개씩 배치한 4열×6행 보드다.
- 모든 보드 타일은 처음부터 선택 가능하다. 생성 시 각 음식이 정확히 3개 존재하므로 올바르게 모으면 항상 해결 가능하다.
- 첫 판은 한 음식의 3개 타일을 서로 떨어진 위치에 배치하고 튜토리얼 강조 대상으로 지정한다. 다시 하기부터는 강조 없이 새 시드로 섞는다.
- 타일을 누르는 즉시 보드에서는 비활성화하고 트레이에 추가한다. 중복 입력 방지를 위해 한 번의 이동·판정이 끝날 때까지 입력을 잠근다.
- **판정 순서:** 타일 추가 → 같은 음식 3개 탐색·제거 → 성공 확인 → 트레이 7칸 실패 확인. 일곱 번째 타일로 트리플이 완성된 경우 실패하지 않는다.

### 점수와 피드백

- 트리플 1개당 100점.
- 이전 트리플 후 4초 안에 다음 트리플을 만들면 연속 보너스 `+25 × 연속 단계`를 주며, 단계는 3(+75)에서 상한이다. 4초가 지나도 점수만 초기화되고 게임은 실패하지 않는다.
- 힌트를 쓰지 않고 첫 시도에 성공하면 완벽 정리 보너스 200점. 성공 화면에는 최종 점수, 소요 시간, 완성한 주문 `8/8`을 표시한다.
- 상단 주문표는 8개의 음식 아이콘을 보여주고, 해당 트리플이 지워질 때 도장을 찍는다. 색뿐 아니라 아이콘·짧은 이름·체크 표시로 상태를 구분한다.

### 종료

- **성공:** 보드 타일이 0개이고 해결 중인 애니메이션이 없을 때. 트레이도 규칙상 비어 있어야 한다.
- **실패:** 트리플 제거를 먼저 처리한 뒤 트레이 길이가 7인 경우. 실패 문구는 “트레이가 가득 찼어요”로 원인을 명시한다.
- 성공·실패 오버레이에는 `다시 하기`를 주 행동으로, `다른 데모 보기`를 보조 CTA로 둔다. 외부 구매·다운로드를 유도하지 않는다.

## 4. 화면 구성

세로형 게임 스테이지는 `max-width: 480px`, `min-height: 100dvh`로 중앙 정렬한다.

1. **상단 HUD:** 제목, 점수, 주문 진행 `0/8`, 소요 시간, 음소거 버튼.
2. **주문표·안내:** 음식 8종의 작은 주문 칩과 최초 튜토리얼/상태 문구. 짧은 화면에서는 주문 칩을 4×2로 접는다.
3. **게임 보드:** 화면의 중심 영역. 4×6 CSS Grid, 타일마다 그림과 1–2글자 음식 이름을 함께 표시한다.
4. **트레이:** 하단 고정 시각 영역에 7개 슬롯과 `트레이 0/7` 텍스트를 둔다. 홈 인디케이터 안전 영역을 침범하지 않는다.
5. **결과 레이어:** 배경을 가리되 현재 판의 맥락은 남긴다. 제목→요약→다시 하기→CTA 순서로 포커스를 이동한다.

## 5. 상호작용과 입력

- **마우스/터치:** 음식 타일 탭/클릭. `touch-action: manipulation`을 적용하고 최소 터치 영역을 44×44px로 유지한다.
- **키보드:** `Tab`/`Shift+Tab`으로 타일과 HUD 버튼 이동, `Enter`/`Space`로 선택. 보드에 포커스가 있을 때 방향키는 4열 기준 인접 타일로 이동하며 제거된 칸은 같은 방향의 다음 유효 타일을 찾는다.
- `R`은 결과 화면에서 다시 하기, `M`은 음소거 토글로 제공하되 폼 요소에 입력 중일 때는 단축키를 무시한다.
- 타일은 네이티브 `<button>`으로 구현하고 포커스 중이거나 판정 잠금 상태인지를 시각적으로 구분한다. 트레이 슬롯은 조작 대상이 아니다.

## 6. 상태·데이터 모델

```js
state = {
  phase: 'tutorial' | 'playing' | 'resolving' | 'won' | 'lost',
  seed, runCount, elapsedMs, startedAt,
  score, comboLevel, lastClearAt, usedHint,
  board: [{ id, foodId, row, col, status: 'board' | 'tray' | 'cleared' }],
  tray: [tileId],                 // 최대 7
  orders: [{ foodId, cleared }], // 정확히 8
  selectedFoodIds: [foodId],
  muted, reducedMotion
}
```

- `FOOD_LIBRARY`는 12개의 `{id, name, palette, shape, pattern}` 메타데이터를 가진다. 판마다 8종만 추출한다.
- 시드 기반 Fisher–Yates 셔플로 재현 가능한 보드를 만든다. 같은 시드로 시작했을 때 보드와 주문 순서는 같아야 한다.
- 파생값(`remainingTiles`, `trayCount`, `clearedOrders`)은 저장하지 않고 상태에서 계산해 불일치를 막는다.
- 주요 순수 함수는 `createGame(seed)`, `selectTile(id)`, `findTriple(tray)`, `resolveTriple(foodId)`, `calculateScore(now)`, `getOutcome()`으로 분리한다.
- DOM 갱신은 단일 `render(state)` 경로로 처리한다. `phase === 'resolving'` 동안 입력을 차단하고 애니메이션 완료 또는 축소 동작 분기 후 다음 상태로 간다.

## 7. 오리지널·절차형 자산

- 음식 12종은 JS 메타데이터로 생성한 단순 인라인 SVG로 제작한다. 예: 삼각 밥, 달걀말이, 완자, 잎채소, 만두, 토마토, 버섯, 새우, 두부, 국수, 과일, 떡. 특정 브랜드 상품이나 기존 이모지 파일을 복제하지 않는다.
- 각 음식은 실루엣, 내부 패턴, 한글 약칭이 달라 흑백·색각 이상 환경에서도 구분된다.
- 주문표, 7칸 트레이, 도시락 패턴 배경, 동전·도장·작은 별 파티클은 CSS 도형과 인라인 SVG로 만든다.
- 이미지·폰트·오디오 파일, CDN, 외부 라이브러리를 내려받지 않는다. 시스템 폰트만 사용해 네트워크가 끊겨도 동일하게 실행한다.

## 8. 모션·오디오

- 타일 이동 140ms, 트리플 축소·도장 180ms, 주문 완료의 작은 별 파티클 350ms, 결과 패널 등장 220ms를 기준으로 한다. 모션은 `transform`과 `opacity`만 사용해 재배치를 유발하지 않는다.
- 첫 튜토리얼 강조는 최대 2회만 맥동하고, 입력 즉시 멈춘다. 실패 시 화면 흔들기 대신 트레이 테두리와 문구로 원인을 알린다.
- 오디오는 첫 사용자 입력 후 Web Audio API로 짧은 탭, 트리플 팝, 성공 3음, 실패 저음만 합성한다. 음소거 버튼은 항상 노출하고 자동 재생은 하지 않는다.
- `prefers-reduced-motion: reduce`에서는 이동·맥동·파티클을 제거하고 0–40ms의 상태 전환 및 정적 체크 표시로 대체한다. 게임 규칙과 판정 시점은 동일하다.

## 9. 접근성

- 문서 언어는 `ko`, 제목·랜드마크·버튼 구조를 사용한다. 각 타일의 접근성 이름은 “달걀말이 타일, 2행 3열” 형식이다.
- 점수·트레이·주문 진행은 화면 텍스트로 항상 보이며, 트리플 완료는 `aria-live="polite"`, 최종 결과는 포커스 가능한 결과 제목으로 전달한다.
- 포커스 링은 배경 대비 3:1 이상, 일반 텍스트는 WCAG AA 대비를 목표로 한다. 색만으로 선택·완료·실패를 표현하지 않는다.
- 시간은 점수 보조 지표일 뿐 제한 시간이 아니므로 느린 입력이나 보조 기술 사용이 실패 원인이 되지 않는다.
- 음소거 상태와 축소 동작 환경에서도 모든 피드백을 텍스트·형태로 확인할 수 있다.

## 10. 반응형 동작

- **320–480px 세로:** 기본 4열 보드. `clamp()`로 타일 크기와 간격을 조정하며 44px 최소 조작 영역을 지킨다. `env(safe-area-inset-*)`를 적용한다.
- **짧은 화면(높이 < 650px):** 장식 여백과 HUD 간격만 축소하고 안내 문구는 한 줄로 줄인다. 보드와 트레이는 스크롤 없이 우선 노출한다.
- **가로/태블릿(너비 ≥ 720px, 가로 방향):** 보드를 왼쪽, HUD·주문표·트레이를 오른쪽에 둔 2열 레이아웃으로 바꿔 세로 넘침을 막는다.
- **데스크톱:** 최대 스테이지 크기를 제한하고 바깥에는 비상호작용 배경만 둔다. 마우스 hover는 부가 효과이며 포커스/선택 정보로 사용하지 않는다.
- 200% 브라우저 확대에서도 주요 조작과 결과 버튼이 잘리거나 겹치지 않아야 하며, 필요 시 문서 전체의 세로 스크롤은 허용한다.

## 11. 구현 개요

각 파일은 `games/bento-triples/` 안에 두며 공유 파일이나 빌드 도구 없이 `index.html`을 직접 열어 실행한다.

- **`index.html`:** 한국어 메타데이터, 게임 랜드마크, HUD, 주문표, 보드, 트레이, 라이브 리전, 결과 `<dialog>` 또는 동등한 접근성 레이어, `<template>` 정의. `style.css`와 `script.js`만 상대 경로로 참조한다.
- **`style.css`:** 색상·간격 토큰, 모바일 우선 Grid/Flex 레이아웃, 44px 타깃, 포커스/상태 스타일, 트레이와 절차형 장식, 결과 레이어, 가로형 미디어 쿼리, `prefers-reduced-motion` 분기.
- **`script.js`:** 음식/SVG 메타데이터, 시드 PRNG와 보드 생성, 이벤트 위임, 키보드 그리드 탐색, 순수 상태 전이와 점수 계산, 단일 렌더러, Web Audio 합성, 타이머 표시, 결과/재시작/CTA 처리.
- ES 모듈·프레임워크·서버 요청·로컬 스토리지에 의존하지 않는다. CTA는 `../../index.html`을 가리키되 링크가 없어도 게임 플레이와 재시작은 온전히 동작한다.

## 12. 인수 시나리오

1. **첫 진입:** Given 새 세션, When 페이지가 열리면, Then 24개 타일·8개 주문·빈 7칸 트레이가 보이고 첫 안전 트리플과 한국어 안내가 표시된다.
2. **일반 선택:** Given 플레이 중, When 활성 타일을 한 번 누르면, Then 타일은 보드에서 트레이로 정확히 한 번 이동하고 중복 입력되지 않는다.
3. **트리플:** Given 같은 음식 2개가 트레이에 있을 때, When 세 번째를 넣으면, Then 세 타일이 제거되고 해당 주문이 완료되며 최소 100점이 추가된다.
4. **경계 판정:** Given 트레이에 6개가 있고 그중 같은 음식 2개가 있을 때, When 일곱 번째 동일 음식을 넣으면, Then 트리플을 먼저 지우고 실패하지 않는다.
5. **실패:** Given 트레이에 6개가 있고 완성 가능한 트리플이 없을 때, When 서로 다른 일곱 번째 타일을 넣으면, Then 입력이 잠기고 원인이 명시된 실패 화면이 열린다.
6. **성공:** Given 마지막 트리플만 남았을 때, When 이를 완성하면, Then 보드·트레이가 비고 성공 화면에 점수·시간·`8/8`이 표시된다.
7. **재시작:** Given 결과 화면, When 다시 하기를 선택하면, Then 새 시드의 24개 타일과 0점 상태로 즉시 시작한다.
8. **키보드:** Given 보드 포커스, When 방향키와 Enter/Space를 사용하면, Then 유효 타일 사이를 예측 가능하게 이동하고 포인터와 같은 판정이 발생한다.
9. **축소 동작:** Given 축소 동작 선호, When 트리플과 결과가 발생하면, Then 맥동·이동·파티클 없이 동일한 상태와 정보를 즉시 확인할 수 있다.
10. **오프라인:** Given 네트워크 차단, When 로컬 `index.html`을 열면, Then 자산 누락이나 콘솔 네트워크 오류 없이 전체 게임을 완료하고 재시작할 수 있다.
