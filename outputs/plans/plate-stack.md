## 1. 기획 기준

- **관찰 근거:** `outputs/frames/group1-006s.png` 3번 패널에는 카운터에 선 손님 2명, 각자의 주문 카드(같은 요리 3개 + 코인 300 / 40), 아래로 뻗은 **6개 세로 접시 스택**, 그리고 첫 컬럼 최상단을 가리키는 **탭 손가락 힌트**가 보인다.
- **정정 반영:** 이 소재는 드래그가 아니라 **탭 기반**이다(stage-00 정정 2건 중 하나). 선택 가능한 대상은 각 컬럼의 **최상단 1장뿐**이며, 그 아래 접시는 위가 빠져야 드러난다.
- **구현 가정(프레임 미확인):** 임시 보관 슬롯의 개수, 라운드 시간, 코인 산식, 클리어 조건은 프레임에서 확정되지 않는다. 아래 값은 20–45초 플레이 프로토타입에 맞춘 독자 설계이며 이 문서를 단일 기준으로 삼는다.
- **플레이어 약속:** “보이는 건 맨 위 한 장뿐. 무엇을 먼저 집을지 한 수 앞을 읽어 손님 줄을 끊기지 않게 흘려보낸다.” 규칙 설명 없이 첫 3회 탭으로 이해되고, 실패는 운이 아니라 **내 선택 때문**이라고 느껴져야 한다.
- **톤:** 밝은 봄 카운터, 또렷한 요리 실루엣, 짧고 경쾌한 서빙 감각. 원본 로고·캐릭터·스크린샷은 일절 사용하지 않는다.

## 2. 1라운드 플레이 루프(목표 30–40초, 상한 60초)

1. **도입 0–2초:** 보드가 아래에서 위로 짧게 정렬되며 손님 2명과 주문 카드가 들어온다. “맨 위 접시를 탭해 주문을 채우세요”와 `시작` 버튼을 표시하고 타이머는 아직 돌지 않는다.
2. **본 플레이 2–50초:** 컬럼 최상단 접시를 탭 → 접시가 **보관 트레이**로 올라간다 → 활성 주문과 자동 매칭되어 카드 슬롯을 채운다. 주문 3칸이 다 차면 손님이 코인을 남기고 떠나고, 대기 중이던 다음 손님이 들어온다.
3. **판정:** 보드의 접시 24장을 모두 비우면 **클리어**, 트레이 3칸이 막히거나 60초가 지나면 **실패**다.
4. **결과 2–5초:** 획득 코인, 서빙한 손님 수, 남은 시간 보너스, 최고 기록과 `다시 하기` · 비상업적 `다른 데모 보기` CTA를 제공한다.

## 3. 규칙, 점수, 성공·실패

### 규칙

- 보드는 **6컬럼 × 4장 = 접시 24장**이다. 각 컬럼은 최상단 1장만 활성(탭 가능)이고 나머지는 비활성이다.
- 주문은 총 **8건**이며 각 주문은 **동일 요리 3장**을 요구한다(24 = 8 × 3). 카운터에는 **항상 2건**이 활성으로 보이고, 하나가 완료되면 대기열의 다음 주문이 그 자리에 들어온다.
- 탭한 접시는 항상 **보관 트레이(3칸)** 로 먼저 이동한다. 이동 직후 **해소 패스**가 돌아, 트레이의 접시 중 활성 주문이 요구하고 아직 빈 슬롯이 있는 것을 앞칸부터 순서대로 주문 카드로 날려 보낸다. 해소는 더 이상 옮길 접시가 없을 때까지 반복한다(주문 완료로 새 주문이 들어오면 그 주문에 대해서도 다시 판정).
- 해소 패스가 끝난 뒤 트레이 3칸이 모두 차 있으면 그 시점에 **실패**다. 즉 “3칸이 차는 것” 자체가 아니라 **차고도 해소되지 않는 상태**가 실패다.
- 애니메이션(접시 이동 220ms) 동안 새 입력을 잠근다. 비활성 접시·빈 컬럼 탭은 무시하며 카운트되지 않는다.

### 보드 생성 — 해결 가능성 보장

무작위 셔플은 트레이 3칸으로 못 푸는 배치를 만든다. 따라서 **역방향 생성**으로 정답 수순을 먼저 만들고 그 수순을 되감아 보드를 만든다.

1. 요리 6종에서 8건의 주문을 뽑는다(동일 요리 중복 허용, 한 종류가 3건을 넘지 않게 제한).
2. 정답 픽 시퀀스 `P`를 만든다. 기본은 주문 순서대로 3장씩 연속이며(트레이 여유 3), 여기에 **트레이 점유가 2를 넘지 않는 범위에서만** 다음 주문의 접시를 앞당겨 끼워 넣어 단조로움을 없앤다. 삽입 시뮬레이션은 실제 게임 규칙(활성 주문 2건, 해소 패스)을 그대로 사용한다.
3. `P`를 **역순으로** 순회하며 각 접시를 높이 4 미만인 컬럼에 쌓는다. 마지막에 6컬럼이 모두 높이 4가 되도록 컬럼 선택을 제약한다.
4. 역순 push 순서가 곧 정방향 pop 순서이므로, `P`는 생성된 보드에서 **반드시 유효한 수순**이다. 생성은 시드 기반이라 버그 재현·QA 고정 보드가 가능하다.
5. 안전망으로, 생성 직후 `P`를 규칙 엔진에 그대로 돌려 클리어되는지 자체 검증한다. 실패하면(로직 회귀) 다른 시드로 최대 20회 재생성하고, 그래도 실패하면 검증된 고정 보드(하드코딩 시드 1개)로 폴백한다.

### 점수

- 주문 완료 시 **코인 = 주문 기본가(40 / 80 / 120 / 200 / 300 중 순환) × 콤보 배수**. 콤보 배수는 트레이를 거치지 않고 **탭 즉시 주문으로 직행한 접시**가 연속될수록 `1.0 → 1.2 → 1.5`(상한)로 오르고, 트레이에 접시가 남는 순간 1.0으로 돌아간다.
- 클리어 시 **남은 시간 × 5코인**을 보너스로 더한다. 실패 시 보너스는 없고 그때까지 번 코인만 남는다.
- 최고 코인은 해당 탭의 `sessionStorage`에만 보관하고, `file://`에서의 저장소 예외는 `try/catch` + 메모리 값으로 대체한다.

### 실패와 회복

- **트레이 막힘:** 막힌 3장을 붉게 강조하고 “보관대가 가득 찼어요”를 표시한다. 마지막에 탭한 접시를 화살표로 짚어 **왜 막혔는지**를 보여준다.
- **시간 종료:** 남은 접시 수와 함께 “시간이 다 됐어요”를 표시한다.
- 두 경우 모두 결과 카드를 1초 이상 강제로 기다리게 하지 않으며, `다시 하기`는 **새 시드**로 완전히 초기화한다(같은 보드 반복 학습을 막는다).
- 실패 직전 1수 되돌리기는 넣지 않는다. 대신 라운드가 짧고 재시작이 즉시라서 마찰이 낮다.

## 5. 입력 설계

### 포인터·터치

- 각 컬럼은 실제 `<button>`이다. 최상단 접시뿐 아니라 **컬럼 전체가 탭 타깃**이라 작은 화면에서도 놓치지 않는다.
- `pointerdown`에서 컬럼이 3px 눌리는 프레스 피드백을 주고, 실제 픽은 `click`(또는 `pointerup` 후 동일 타깃)에서 확정한다. 드래그로 컬럼 밖에 나갔다 놓으면 취소한다.
- 보드에 `touch-action: manipulation`을 적용해 더블탭 확대와 스크롤 튐을 막는다. 다중 터치는 첫 포인터만 인정한다.
- 이동 애니메이션 중 눌린 컬럼은 `disabled`가 아니라 `aria-disabled`로 잠가 포커스를 잃지 않게 한다.

### 키보드

- 컬럼 6개는 하나의 툴바(`role="toolbar"`)로 묶어 **Tab 1회**에 들어오고, `←/→`(및 `Home/End`)로 컬럼을 이동한다. 보드 전체가 6번 Tab을 먹지 않게 한다.
- `Enter` 또는 `Space`로 현재 컬럼 최상단을 픽한다. 시작/다시 하기/음소거는 일반 탭 순서를 따른다.
- 각 컬럼 버튼의 접근성 이름은 `"3번 줄, 맨 위 연어초밥, 남은 4장"` 형식으로 갱신한다. 포커스 링은 항상 선명하게 유지한다.
- 조작 안내 문구는 마지막 입력 방식에 따라 “접시를 탭하세요” / “방향키로 이동, Enter로 집기”로 바꾼다.

## 6. 상태 모델

```text
phase: intro | playing | moving | result
columns: DishId[][]           // 6개 배열, 마지막 원소가 최상단
tray: (DishId | null)[]       // 길이 3
activeOrders: [Order, Order]  // Order = { dish, filled: 0..3, coin }
orderQueue: Order[]           // 남은 대기 주문
coins: number
combo: 0 | 1 | 2              // 배수 1.0 / 1.2 / 1.5 인덱스
timeRemainingMs: number       // 최대 60,000
result: null | { coins, served, bonus, cleared, reason }
inputMode: pointer | keyboard
muted: boolean                // 기본 true
seed: number
roundId: number               // 오래된 타이머/애니메이션 콜백 무효화
```

- 허용 전이는 `intro → playing → moving → playing` 반복 후 `result`, 또는 `playing → result(time-out)`이다.
- **규칙은 순수 함수로 분리한다:** `pick(state, columnIndex) → state'`, `resolve(state) → state'`, `isLost(state)`, `isCleared(state)`. DOM을 모르는 함수라 보드 생성 검증기와 게임 본체가 **같은 코드**를 쓴다.
- 애니메이션은 상태 전이 뒤에 붙는 연출일 뿐이다. 렌더는 항상 최신 `state`에서 파생하므로 애니메이션이 끊겨도 화면과 규칙이 어긋나지 않는다.
- 타이머·애니메이션 콜백은 생성 당시 `roundId`가 현재 값과 같을 때만 상태를 바꾼다.

## 7. 오리지널 에셋, 모션, 오디오

- 외부 이미지·폰트·로고 없이 **CSS와 인라인 SVG만** 사용하고, 시스템 산세리프 글꼴을 쓴다. 네트워크 요청 0건.
- **요리 6종:** 연어초밥 · 주먹밥 · 새우튀김 · 마끼 · 우동 · 규동을 각 24×24 뷰박스의 단순 SVG 심볼로 그린다. `<symbol>` 1벌을 `<use>`로 재사용해 DOM·페인트 비용을 낮춘다.
- **변별력 규칙:** 6종은 **색상 + 실루엣 + 보조 형태 3중**으로 구분한다(예: 원형/삼각/막대 실루엣 차이). 색맹 시뮬레이션에서도 구분되어야 하며, 주문 카드에는 아이콘과 함께 **요리 이름 텍스트**를 항상 표기한다.
- **접시 스택:** 최상단은 요리 아이콘 + 흰 접시 원반, 아래 장들은 2px 타원 테두리를 4px 간격으로 겹쳐 두께로만 표현한다. 컬럼 하단에 남은 장수 배지를 둔다.
- **손님:** 상표·특정 캐릭터를 모사하지 않는 중립 실루엣 2종(머리 모양만 다른 단색 형태)과 말풍선형 주문 카드로 처리한다.
- **모션:** 픽 220ms(접시가 컬럼 → 트레이로 호를 그리며 이동), 주문 충전 180ms, 주문 완료 시 코인 팝 320ms, 손님 교체 260ms. 파티클은 코인 아이콘 최대 6개를 재사용 풀로 돌린다.
- **오디오:** 기본 음소거. 사용자가 켠 뒤에만 Web Audio API로 픽 클릭음, 충전 2음, 완료 3음, 실패 1음을 절차 생성한다. 음원 파일·자동 재생·진동 API는 쓰지 않는다.

## 8. 접근성·감소된 모션

- `main`, 실제 `button`, 의미 있는 제목 구조를 사용한다. 주문 카드는 `"연어초밥 3개 중 1개 완료, 300코인"`으로 읽히게 `aria-label`을 갱신한다.
- 타이머·코인은 시각적으로만 갱신하고, `aria-live="polite"` 영역에는 **픽 결과 · 주문 완료 · 트레이 잔여 1칸 경고 · 10초/5초 · 종료**만 알린다(낭독 폭주 방지).
- 트레이 경고와 실패는 색상 외에 아이콘·문구로 함께 전달한다. 본문/버튼은 WCAG AA 대비를 목표로 하고 핵심 텍스트는 16px 이상이다.
- `prefers-reduced-motion: reduce`에서는 이동 호·코인 팝·손님 교체 연출을 제거하고 80ms 이하의 위치 스냅으로 대체한다. 규칙과 결과는 동일하다.
- 오디오 없이도 모든 정보를 얻을 수 있으며 음소거 상태와 버튼 레이블(`소리 켜기/끄기`)을 항상 노출한다.

## 9. 반응형 동작

- `100svh`와 `env(safe-area-inset-*)`를 쓰고, 게임 셸은 모바일 세로에서 화면 폭 전체·최대 480px로 중앙 정렬한다.
- 320×568에서도 HUD·카운터·트레이·6컬럼이 잘리지 않도록 컬럼 폭은 `clamp()`와 `minmax()` 그리드로 잡고, 컬럼 간격은 최소 6px를 유지한다. 6컬럼은 어떤 폭에서도 **줄바꿈하지 않는다**(줄이 바뀌면 “맨 위 한 장” 규칙의 공간 인지가 깨진다).
- 폭 720px 이상에서는 셸을 최대 760px까지만 확장하고 아이콘을 비례 확대한다. 무한 확대는 하지 않는다.
- 높이 550px 이하의 가로 화면에서는 HUD를 한 줄로 축약하고 카운터를 보드 좌측으로 옮기되, **DOM 순서와 탭 순서는 바꾸지 않는다**.
- 리사이즈·회전 시 진행 상태·타이머·트레이 내용은 보존하고 좌표만 다시 측정한다. 진행 중인 이동 애니메이션은 즉시 종료 위치로 스냅한다.
- 200% 텍스트 확대에서는 결과 카드 내부만 세로 스크롤을 허용하고 보드와 주 버튼은 유지한다.

## 10. 구현 개요

`games/game-03/`은 공유 파일이나 외부 의존성이 없는 독립 디렉터리다. 파일을 직접 열어도 동작해야 하며 네트워크 요청을 만들지 않는다.

### `games/game-03/index.html`

- 반응형 메타 태그, 의미 있는 `main`, HUD, 카운터(주문 카드 2), 트레이(3칸), 컬럼 툴바(버튼 6), 상태 안내, 시작/다시 하기/CTA, 비파괴적 결과 레이어를 정의한다.
- 요리 6종 SVG `<symbol>`과 접근성 제목을 인라인으로 두고, CSS/JS만 상대 경로 `./style.css`, `./script.js`로 연결한다.
- CTA는 `../../index.html` 같은 포트폴리오 내부 링크 또는 비상업적 더미 버튼만 사용하며 앱스토어·브랜드 링크는 넣지 않는다.

### `games/game-03/style.css`

- 색상·간격·레이어·안전영역을 CSS 변수로 정의하고 세로 기본 레이아웃 + 낮은 가로 화면 미디어 쿼리를 구현한다.
- 컬럼/접시/트레이/주문 카드의 상태 클래스(`is-top`, `is-locked`, `is-warning`, `is-complete`), 포커스 스타일, 44px 이상 입력 영역, `prefers-reduced-motion` 대체 규칙을 담당한다.
- 이미지 URL, 외부 `@import`, 공유 스타일시트를 사용하지 않는다.

### `games/game-03/script.js`

- `CONFIG`(컬럼 6·높이 4·트레이 3·활성 주문 2·60초·코인표), 시드 RNG(`mulberry32`), `generateBoard(seed)`(역방향 생성 + 자체 검증), 순수 규칙 함수 `pick / resolve / isLost / isCleared`, `render`, `finishRound`로 분리한다.
- 포인터와 키보드를 같은 `pick(columnIndex)` 경로로 합치고, 입력 잠금·다중 터치·취소된 포인터를 방어한다.
- `requestAnimationFrame` 기반 경과 시간 타이머, `roundId` 기반 오래된 콜백 차단, DOM 캐시 1회 생성 후 변경분만 갱신, 선택적 Web Audio를 구현한다.
- 규칙 함수는 DOM과 무관한 순수 함수로 두어 보드 생성 검증과 QA 재현에 그대로 재사용한다.

## 11. 인수 시나리오

1. **첫 진입:** 360×640에서 스크롤 없이 손님 2명·주문 2장·트레이 3칸·6컬럼(각 4장)이 보이고 타이머는 시작 전 감소하지 않는다.
2. **직행 서빙:** 활성 주문이 요구하는 요리를 탭하면 트레이에 머무르지 않고 주문 카드로 직행하며 콤보 배수가 오른다.
3. **보관 후 해소:** 지금 필요 없는 접시를 탭하면 트레이에 남고, 이후 그 요리를 요구하는 주문이 활성화되는 순간 **자동으로** 주문으로 이동한다.
4. **주문 교체:** 주문 3칸이 차면 코인이 더해지고 손님이 교체되며, 새 주문 기준으로 트레이 해소 패스가 즉시 다시 돈다.
5. **해결 가능성:** 임의의 시드 500개에 대해 생성기의 정답 수순 `P`가 항상 클리어에 도달한다(자동 검증).
6. **패배 판정:** 해소 후에도 트레이 3칸이 모두 차면 그 즉시 실패 결과가 뜨고 입력이 잠기며, 막힌 접시와 마지막 픽이 강조된다.
7. **시간 실패:** 60초 안에 보드를 비우지 못하면 남은 접시 수와 함께 시간 종료 결과가 나온다.
8. **입력 동등성:** 탭과 방향키+Enter가 같은 `pick()` 경로를 쓰고, 취소된 포인터·비활성 접시 탭은 상태를 바꾸지 않는다.
9. **재시작:** `다시 하기`는 새 시드로 보드·트레이·주문·코인·타이머를 초기화하고, 이전 타이머가 새 라운드를 종료시키지 않는다.
10. **접근성:** 키보드만으로 시작–클리어–재시작이 가능하고, 포커스가 보이며 주문 진행·트레이 경고·결과를 화면 낭독기로 이해할 수 있다.
11. **감소된 모션:** OS 감소된 모션에서 파티클·이동 호 없이 동일한 규칙과 결과가 즉시 제공된다.
12. **독립 실행:** 네트워크를 차단하고 `games/game-03/index.html`을 직접 열어도 게임·절차 그래픽·선택적 오디오가 동작하고 콘솔 오류가 없다.

## 13. 유형·견적 근거

- **분류:** `B — 보드상태 퍼즐`, 복잡도 `medium`.
- **투입 근거:** 로직 3일(해결 가능성 보장 생성기 + 순수 규칙 엔진 + 해소 연쇄 + 상태/타이머), 아트 2일(요리 6종 SVG·접시 스택·손님·주문 카드·트레이·서빙 모션), QA 1.5일(배치 검증 자동화, 반응형 6컬럼, 접근성·브라우저), 합계 약 **6.5인일**.
- **핵심 리스크는 배치의 해결 가능성**이다. 무작위 셔플은 눈에 띄는 빈도로 불가능 보드를 만들고, 그 실패는 “내 실수”가 아니라 “게임 탓”으로 읽혀 광고 소재로서 치명적이다. 역방향 생성 + 자동 검증을 별도 공수로 잡은 이유다. 두 번째 리스크는 주문 완료 → 손님 교체 → 트레이 재해소로 이어지는 **상태 전이의 연쇄**이며, 규칙을 순수 함수로 분리해 테스트 가능하게 만드는 것으로 대응한다.
- 계획 범위는 선임 HTML5 개발 1명 + 부분 UI/아트·QA, 단일 레벨, 한국어, 내부 QA와 1회 수정 기준으로 **7–10영업일 / ₩6.5M–₩9.0M(VAT 별도)**다. 브랜드 일러스트, 전문 음원, 추가 레벨·난이도 커브, 분석/광고 SDK, 다국어, 네트워크 배포 패키징은 별도 범위다.
