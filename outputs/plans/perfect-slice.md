# 퍼펙트 슬라이스(Perfect Slice) 제작 계획

> **구현 경로는 `games/game-02/` 다.** 이 문서가 아니라 `games/game-02/game.json` 이 경로·슬러그·견적의 근거이며, 목록·링크는 `games/*/game.json` 을 글롭해 만든다(검증: `scripts/check-hub.mjs`). 아래 본문의 경로는 실제 디렉터리에 맞춰 갱신했다.

## 1. 기획 기준

- **관찰 근거:** `~00:06`의 패널에는 오이, 칼, 제한 칼질 안내와 남은 횟수가 보인다. 핵심 메커닉은 제한된 칼질로 오이를 균등하게 나누고 두께 편차로 평가받는 것이다.
- **구현 가정:** 원본에서 확인되지 않은 라운드 시간, 성공 기준, 결과 화면은 이 프로토타입의 20–45초 플레이에 맞춰 아래와 같이 고정한다.
- **플레이어 약속:** “짧은 순간에 셰프처럼 정확한 칼질을 하고, 가지런한 단면과 즉각적인 점수 피드백에서 손맛을 얻는다.” 한 손 터치로 이해되되 정교하게 자를수록 결과가 눈에 띄게 좋아야 한다.

## 2. 1라운드 플레이 루프(약 25–35초)

1. **도입 0–3초:** 오이 위에 목표 6등분 가이드가 잠시 점멸한다. “5번 잘라 6조각을 똑같이!”와 `시작` 버튼을 표시하며 타이머는 아직 돌지 않는다.
2. **조준·절단 3–25초:** 칼을 좌우로 옮긴 뒤 놓아 자른다. 유효 절단마다 칼 내려찍기, 단면 벌어짐, 작은 수분 파티클과 남은 칼질 수 갱신을 280ms 안에 보여준다. 총 5회의 유효 절단을 반복한다.
3. **판정 1–2초:** 여섯 조각을 살짝 분리해 폭 차이를 한눈에 보여주고 정확도 점수를 0부터 최종값까지 짧게 올린다.
4. **결과 3–6초:** 성공/재도전 메시지, 점수, 최고 점수, `다시 자르기`와 비상업적 `다른 데모 보기` CTA를 제공한다.

`시작` 이후 제한 시간은 25초이며, 빠른 플레이는 약 20초, 신중한 플레이와 결과 확인까지도 45초를 넘지 않게 한다.

## 3. 규칙, 점수, 성공·실패

### 규칙

- 오이 전체 길이를 `0..1`로 보고 5개의 서로 다른 위치에 유효 절단을 만들어 6조각으로 나눈다.
- 기존 절단선 또는 양 끝에서 오이 길이의 4.5% 이내에 놓으면 무효다. 칼질 수는 차감하지 않고 “조금 더 안쪽으로” 안내하며 짧은 진동 표현만 낸다.
- 절단 애니메이션 280ms 동안 추가 입력을 잠근다. `pointercancel`, 창 포커스 이탈 또는 오이 밖에서 취소된 드래그는 절단으로 처리하지 않는다.
- 남은 유효 절단이 0이 되면 즉시 채점한다. 제한 시간이 먼저 0이 되면 라운드 실패다.

### 점수식

- 정렬된 경계 `B = [0, ...cuts, 1]`에서 조각 폭 `wᵢ = Bᵢ₊₁ - Bᵢ`, 평균 폭 `μ = 1 / N`을 구한다.
- 정규화 편차 `d = sqrt(Σ(wᵢ - μ)² / N) / μ`를 사용한다.
- 최종 정확도는 `round(100 × clamp(1 - d / 0.60, 0, 1))`점이다. 완전한 균등 분할은 100점이며, 조각 간 편차가 커질수록 단조롭게 낮아진다.
- 65점 이상은 **성공**, 64점 이하는 **재도전**이다. 90–100은 `완벽한 칼질`, 80–89는 `셰프급`, 65–79는 `좋아요`, 0–64는 `한 번 더` 등급을 함께 표시한다.
- 시간은 압박 요소일 뿐 점수 보너스로 더하지 않아 “두께 편차 기반 점수”라는 약속을 흐리지 않는다. 최고 점수는 해당 탭의 `sessionStorage`에만 보관하되, `file://` 환경의 저장소 예외는 `try/catch`와 메모리 값으로 대체한다.

### 실패와 회복

- **시간 종료:** 미완성 조각 수와 함께 “시간이 다 됐어요”를 표시하고 즉시 재시작할 수 있다.
- **낮은 정확도:** 완주는 인정하되 성공 연출은 생략하고 `다시 자르기`를 주 행동으로 노출한다. `다른 데모 보기`는 보조 행동으로 계속 접근 가능하게 둔다.
- 실패 후에도 결과를 1초 이상 강제로 기다리게 하지 않으며, `다시 자르기`는 초기 상태를 완전히 복원한다.

## 4. 화면 구성

세로형 360×640을 기준으로, 한 화면 안에서 스크롤 없이 구성한다.

| 영역 | 비중/역할 | 내용 |
|---|---|---|
| 상단 HUD | 높이 약 16% | 제목, 25초 타이머, `남은 칼질 5/5`, 음소거 토글 |
| 작업대 | 높이 약 58% | 나무 도마, 가로 오이, 이동 칼, 절단 가이드·피드백, 우측 상단 심사 스티커 |
| 하단 안내 | 높이 약 26% | 현재 조작 문구, 정확도 자리, 시작/재시작 버튼과 CTA |
| 결과 레이어 | 작업대 위 모달형 카드 | 최종 점수·등급·최고 점수. 배경을 완전히 가리지 않아 조각 결과가 보이게 함 |

칼 손잡이의 실질 입력 영역은 최소 52×52px, 모든 버튼은 최소 44×44px로 한다. 타이머는 숫자와 원형 진행 표시를 함께 쓰고, 성공/실패는 색상 외에 아이콘·문구로 구분한다.

## 5. 입력 설계

### 포인터·터치

- 칼 손잡이를 누르면 `setPointerCapture()`로 드래그를 소유하고, 좌우 이동만 오이 좌표로 환산한다. 세로 손떨림은 무시한다.
- 드래그 중 칼 아래에 1px 절단 예상선을 표시한다. `pointerup` 시 현재 위치에서 절단한다.
- 작업대에는 `touch-action: none`을 적용해 조준 중 페이지 스크롤·브라우저 제스처와 충돌하지 않게 한다. 다중 터치는 첫 포인터만 인정한다.
- 손가락이 칼 그림을 가리지 않도록 터치 중 칼을 포인터보다 24px 위에 렌더링하되, 판정 위치는 예상선으로 명확히 보여준다.

### 키보드

- 칼은 포커스 가능한 슬라이더 역할(`role="slider"`)을 갖는다. `←/→`는 오이 길이의 1.5%, `Shift+←/→`는 5%씩 이동한다.
- `Space` 또는 `Enter`로 현재 위치를 절단한다. 시작/재시작/음소거는 자연스러운 탭 순서와 기본 버튼 동작을 사용한다.
- 포커스 링을 항상 선명하게 표시하고, 조작 안내는 마지막 입력 방식에 따라 “드래그 후 놓기” 또는 “방향키 + Space”로 바꾼다.

## 6. 절단 지오메트리와 상태 모델

### 좌표·판정

- 모델은 화면 픽셀이 아닌 정규화 좌표를 단일 진실 공급원으로 쓴다. 포인터의 `clientX`를 매 입력 시 최신 오이 `getBoundingClientRect()`에 투영해 `x = clamp((clientX-left)/width, 0, 1)`로 구한다.
- `cuts`는 항상 오름차순으로 저장한다. 유효성은 `min(|x-b| for b in [0, ...cuts, 1]) >= 0.045`로 판정한다.
- 렌더 시 경계 배열에서 조각 구간을 다시 파생한다. 리사이즈 후에도 정규화 좌표를 새 폭에 매핑하므로 점수와 절단 위치가 바뀌지 않는다.
- 시각적 “물리”는 엔진 없이 결정론적으로 처리한다. 새 절단선 좌우 조각을 각각 4–8px 밀고 ±1.5° 회전한 뒤 안정 위치로 되돌리며, 모델 좌표 자체에는 흔들림 값을 기록하지 않는다.

### 상태

```text
phase: intro | playing | cutting | result
cuts: number[]                 // 0..1, 정렬된 유효 절단 위치
knifeX: number                 // 현재 조준 위치
cutsRemaining: 5 - cuts.length
timeRemainingMs: number        // 최대 25,000
result: null | { score, grade, success, reason }
inputMode: pointer | keyboard
muted: boolean                 // 기본 true
roundId: number                // 이전 타이머/애니메이션 무효화
```

허용 전이는 `intro → playing → cutting → playing` 반복 후 `result`, 또는 `playing → result(time-out)`이다. 새 라운드는 `result → intro`가 아니라 곧바로 초기화된 `playing`으로 들어가 재도전 마찰을 줄인다. 타이머와 애니메이션 콜백은 생성 당시 `roundId`가 현재 값과 같을 때만 상태를 바꾼다.

## 7. 오리지널 에셋, 모션, 오디오

- 외부 이미지·폰트·로고 없이 CSS와 인라인 SVG로만 제작한다. 시스템 산세리프 글꼴을 사용한다.
- **도마:** CSS 그라디언트와 저대비 선 패턴으로 만든 따뜻한 나무 표면.
- **오이:** 직접 작성한 SVG 캡슐 경로, 껍질 그라디언트, 씨앗 타원 패턴. 각 조각은 동일 원본 경로를 구간별 `clipPath`로 자르고 별도 `<g>`로 렌더링한다.
- **칼·심사 스티커:** 단순 SVG 도형으로 제작한다. 특정 게임 캐릭터나 상표를 모사하지 않는 중립적인 셰프 얼굴/별 아이콘을 쓴다.
- **파티클:** 작은 원·물방울 SVG/CSS 요소를 최대 10개만 재사용해 저사양 기기에서도 과도한 DOM 생성을 막는다.
- 칼 낙하 120ms, 충격 40ms, 조각 이격 120ms로 280ms 안에 끝낸다. 결과 점수 카운트업은 500ms, 성공 카드 진입은 240ms 이내다.
- 오디오는 기본 음소거다. 사용자가 켠 뒤에만 Web Audio API로 짧은 절단 노이즈, 성공 2음, 실패 1음을 절차 생성한다. 음원 파일·자동 재생·진동 API는 사용하지 않는다.

## 8. 접근성·감소된 모션

- `main`, 실제 `button`, 의미 있는 제목 구조를 사용한다. 칼 슬라이더에는 현재 위치 백분율과 남은 칼질을 접근성 이름/값으로 제공한다.
- 남은 시간·칼질 수는 계속 읽어 화면 낭독을 방해하지 않도록 시각적으로만 갱신하고, 10초·5초·완료 시점과 유효/무효 절단만 `aria-live="polite"` 상태 영역에 알린다.
- 본문/버튼은 WCAG AA 명도 대비를 목표로 하며, 16px 미만의 핵심 텍스트를 쓰지 않는다. 점수와 상태는 색상에만 의존하지 않는다.
- `prefers-reduced-motion: reduce`에서는 파티클·흔들림·점수 카운트업을 제거하고, 칼/조각 전환을 80ms 이하의 단순 상태 변경으로 대체한다.
- 음소거 상태와 버튼 레이블(`소리 켜기/끄기`)을 항상 노출한다. 플레이는 오디오 없이도 모든 정보를 얻을 수 있다.

## 9. 반응형 동작

- `100svh`와 `env(safe-area-inset-*)`를 사용하고, 게임 셸은 모바일 세로에서 화면 폭 전체·최대 480px로 중앙 정렬한다. 폭 720px 이상의 태블릿/가로 화면에서는 최대 760px까지 확장한다.
- 320×568에서도 HUD·작업대·주요 버튼이 잘리지 않도록 높이는 `clamp()`로 조정한다. 200% 텍스트 확대 시에는 결과 카드 내부만 세로 스크롤을 허용하고 조작 영역과 주 버튼은 유지한다.
- 태블릿/데스크톱에서는 게임 셸을 무한 확대하지 않고 작업대만 최대 720px까지 확장한다. 칼/오이 비율과 최소 입력 크기는 유지한다.
- 높이 550px 이하의 가로 화면에서는 상단 HUD를 한 줄로 축약하고 안내 문구를 작업대 하단 오버레이로 옮긴다. DOM 순서와 탭 순서는 바꾸지 않는다.
- `ResizeObserver` 또는 `resize` 이벤트에서 오이 사각형만 다시 측정하고, 진행 중 상태·타이머·정규화 절단 좌표는 보존한다.

## 10. 구현 개요

`games/game-02/`는 다른 게임과 공유 파일이나 외부 의존성이 없는 독립 디렉터리다. 파일을 직접 열어도 동작해야 하며 네트워크 요청을 만들지 않는다.

### `games/game-02/index.html`

- 반응형 메타 태그, 의미 있는 `main`, HUD, 작업대, 상태 안내, 시작/재시작/CTA 버튼과 비파괴적 결과 레이어를 정의한다.
- 오이·칼 SVG의 원본 도형과 접근성용 제목을 인라인으로 둔다. CSS/JS만 상대 경로 `./style.css`, `./script.js`로 연결한다.
- CTA는 `../../index.html` 같은 포트폴리오 내부 상대 링크 또는 비상업적 더미 버튼만 사용하며 앱스토어·브랜드 링크는 넣지 않는다.

### `games/game-02/style.css`

- 색상·간격·레이어·안전영역을 CSS 변수로 정의하고, 세로 기본 레이아웃과 낮은 가로 화면 미디어 쿼리를 구현한다.
- 도마/칼/오이 보조 질감, 절단·결과 상태 클래스, 포커스 스타일, 44px 이상 입력 영역과 `prefers-reduced-motion` 대체 규칙을 담당한다.
- 이미지 URL, 외부 `@import`, 공유 스타일시트를 사용하지 않는다.

### `games/game-02/script.js`

- `CONFIG`, 단일 `state`, `startRound/resetRound`, `isValidCut`, `commitCut`, `deriveSegments`, `calculateScore`, `render`, `finishRound`로 게임 규칙을 분리한다.
- Pointer Events와 키보드를 같은 `knifeX → commitCut()` 경로로 합치고, 포인터 캡처·다중 입력·취소를 방어한다.
- `requestAnimationFrame` 기반 경과 시간 타이머, `roundId` 기반 오래된 콜백 차단, SVG 조각/파티클 풀 렌더링, 선택적 Web Audio를 구현한다.
- DOM 캐시는 초기화 시 한 번 만들고, 타이머 중에는 바뀐 텍스트/속성만 갱신한다. 점수 함수는 DOM과 독립된 순수 함수로 둔다.

## 11. 인수 시나리오

1. **첫 진입:** 360×640 화면에서 게임을 열면 스크롤 없이 목표, 시작 버튼, 오이, 5회의 남은 칼질이 보이고 타이머는 시작 전 감소하지 않는다.
2. **균등 분할:** 1/6, 2/6, 3/6, 4/6, 5/6 위치에서 유효 절단하면 6조각, 100점, `완벽한 칼질` 성공 결과가 나온다.
3. **편차 반영:** 같은 5회 절단이라도 폭의 분산이 커지면 점수가 반드시 낮아지고, 65점 미만이면 재도전 결과가 나온다.
4. **무효 절단:** 기존 경계에서 4.5% 미만 위치에 놓으면 안내가 표시되며 남은 칼질, `cuts`, 점수에는 변화가 없다.
5. **시간 실패:** 시작 후 25초 안에 5회를 끝내지 못하면 입력이 잠기고 시간 종료 결과와 즉시 사용 가능한 재시작 버튼이 나온다.
6. **입력 동등성:** 터치/마우스 드래그 후 놓기와 방향키+Space 모두 같은 좌표 검증·점수 로직을 사용한다. 취소된 포인터는 절단하지 않는다.
7. **재시작:** 결과에서 다시 자르기를 누르면 조각, 점수, 남은 칼질, 타이머가 초기화되고 이전 타이머가 새 라운드를 종료시키지 않는다.
8. **접근성:** 키보드만으로 시작부터 결과·재시작까지 진행 가능하고, 포커스가 보이며 성공/실패 및 주요 이벤트를 화면 낭독기로 이해할 수 있다.
9. **감소된 모션:** OS 감소된 모션을 켜면 파티클·흔들림·카운트업 없이 동일한 규칙과 결과가 즉시 제공된다.
10. **독립 실행:** 네트워크를 차단하고 `games/game-02/index.html`을 직접 열어도 게임, 절차 그래픽, 선택적 오디오가 동작하며 콘솔 오류가 없다.
