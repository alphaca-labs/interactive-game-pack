# Pixel Pour 제작 계획

## 1. 플레이 약속과 범위

**한 문장 약속:** 색과 문양이 표시된 펠릿 묶음을 같은 팔레트 레인으로 빠르게 옮겨, 쏟아 오르는 펠릿이 38초 안에 숨겨진 16×16 픽셀 그림을 완성하게 한다.

- 원본에서 관찰된 `부분 완성 픽셀 아트 + % 진행률 + 색상 레인 + 하단 펠릿 보드`만 메커닉 근거로 삼는다. 타이밍, 점수, 실패 규칙은 이 프로토타입의 제작 가정이다.
- **근거 프레임 재확인(`outputs/frames/group2-140s.png` 1번 패널):** 상단 픽셀 캔버스, `55%` 전체 진행 막대, 캔버스로 이어지는 궤적선, **레인별 개별 퍼센트(27·35·97·54·39·45·68%)를 단 색상 슬롯 약 7~9개**, 하단의 **약 7열×4행 펠릿 보드**가 확인된다. 즉 원본은 "레인마다 채움률이 따로 오른다"는 정보를 노출한다.
- **의도적 축소 2건(근거 대비):** ① 색상 레인을 9개가 아닌 **6개**로 줄인다 — 문양 1:1 대응과 44px 타깃을 360px 폭에서 동시에 만족시키기 위해서다. ② 펠릿 보드는 전량 노출이 아니라 **현재 3개 배치 + 남은 잔량 표시**로 바꾼다 — 20~45초 광고 루프에서 탐색 시간보다 결정 속도가 중요하기 때문이다. 대신 **레인별 퍼센트 표기는 원본대로 유지**해 정보 밀도를 지킨다.
- 단일 레벨, 한국어 UI, 논커머셜 포트폴리오 데모로 제작한다. 레시피(픽셀 도안)는 재시작 체감을 위해 **2종**을 싣고 번갈아 출제한다.
- 마지막 화면의 CTA는 `다른 데모 보기`로 표기하며 스토어 링크나 상용 브랜드를 사용하지 않는다.

## 2. 20–45초 코어 루프

1. **이해(0–3초):** 레인 하나와 같은 문양의 첫 배치가 두 번 호흡하듯 강조된다. `같은 색·문양으로 옮기세요` 힌트를 노출하고, 첫 입력 전까지 타이머는 시작하지 않는다.
2. **선택·운반(1–2초/회):** 하단에 노출된 3개의 배치 중 하나를 드래그하거나 키보드로 선택한다.
3. **분류(0.4초):** 6개 팔레트 레인 중 같은 색·문양에 놓는다. 올바르면 펠릿 6–8개가 화면 상단으로 올라가고, 틀리면 배치가 원래 자리로 복귀한다.
4. **즉시 보상(0.3–0.6초):** 맞게 놓은 배치가 레시피 맵의 미완성 셀을 채우고, 퍼센트·콤보·점수가 갱신된다.
5. **반복(15개 배치):** 현재 3개 중 하나가 사용되면 다음 배치가 큐 뒤에서 보충된다. 후반 80%에서 배경 리듬과 보상음이 한 단계 상승한다.
6. **결과(20–45초):** 100%를 채우면 1.2초 완성 연출 후 점수·최대 콤보를 보여 준다. 38초가 끝나면 미완성 셀을 강조하고 즉시 재시작을 제공한다.

목표 플레이 시간은 28–35초이며, 숙련자는 약 20초에 완료할 수 있고 오류 2–3회가 있어도 45초 안에 결과를 본다.

## 3. 룰 시스템

### 레시피·픽셀·팔레트

- 레시피는 원본 프레임을 복제하지 않은 **16×16 원천 픽셀 아트 2종 — `A. 김 나는 머그컵`, `B. 체리 컵케이크`**로 한다. 두 도안 모두 투명 셀을 제외한 **100–108개 셀을 15개 배치(배치당 6–8셀)로 균등 분할**하며, A는 105셀이다. 도안은 JS 배열 데이터일 뿐이라 로직·렌더러는 공유한다.
- 첫 플레이는 A, 재시작마다 A↔B가 번갈아 출제된다. 어떤 도안이든 배치 수·타이머·점수 규칙은 동일해 난이도 차이가 생기지 않는다.
- 색상은 잔상이 남지 않도록 배경 `#FFF4DC`, 윤곽 `#25283B`, 레드 `#E85D5D`, 오렌지 `#F5A642`, 옐로 `#F4D35E`, 그린 `#3FAE78`, 블루 `#4385D1`, 퍼플 `#8A5BD1`로 제한한다.
- 6색에 `원·삼각·+·마름모·물결·별`을 1:1로 대응시켜 색만으로 정답을 구분하지 않도록 한다. 펠릿 배치·레인·선택 유령에 같은 문양을 반복한다.
- 픽셀은 정수 배율로 확대하고 `image-rendering: pixelated`와 1px 내부 간격을 적용한다. 중간색·블러·안티앨리어싱 효과는 쓰지 않는다.
- 진행 중 미완성 셀은 연한 윤곽만, 완성 셀은 제색으로 표시한다. 다음 채워질 셀의 스포일러는 노출하지 않는다.

### 펠릿·파티클

- 배치 하나는 레시피의 같은 색 미완성 셀 6–8개와 정확히 대응한다. 피할 수 없는 막힌 상태가 없도록 배치 큐는 항상 정답 레인을 가진다.
- 펠릿은 6–10px 정사각형으로 그리고 레인 진입 시 320ms 베지어 경로를 따라 레시피로 상승한다. 화면 위 시각 파티클은 최대 96개 풀에서 재사용한다.
- 파티클 추락·반발은 충돌 물리가 아닌 시드 기반 공식으로 표현한다. 충돌 해석은 없으며 파티클은 판정·점수에 영향을 주지 않는 시각 보상이다.
- 오답은 160ms 좌우 흔들림, 레인 경계 밝힘, `문양이 달라요`를 동시에 제공하고 배치를 소모하지 않는다.

### 점수·승리·실패

- 정답 점수는 `100 × 콤보 배율 + 반응 보너스`다. 콤보 배율은 1.0배에서 정답당 0.1씩 올라 2.0배에서 멈춘다. 반응 보너스는 배치 노출 후 1.2초 이내 50점, 2.0초 이내 25점, 이후 0점이다.
- 오답은 75점 감점(최소 0점), 콤보 초기화, 남은 시간 2초 감소다. 드래그 취소나 레인 밖 드롭은 오답으로 치지 않는다.
- **승리:** 38초 안에 15개 배치를 모두 처리해 레시피 100% 완성. 남은 시간 × 20점을 완료 보너스로 더한다.
- **실패:** 진행률이 100%가 되기 전 타이머가 0이 됨. 완성 직전의 손실감을 피하기 위해 타이머 0 시점에 배치가 이미 정답 레인에 드롭되었다면 해당 판정까지 처리한다.
- 결과 화면은 `다시 채우기`를 주 버튼, `다른 데모 보기`를 부 버튼으로 둔다. 재시작 시 레시피는 A↔B로 교대하고 배치 순서는 시드로 재생성한다.

## 4. 화면 구성과 입력

### 레이아웃

기준 뷰포트는 360×640px 세로형이며 순서는 다음과 같다.

1. **상단 9%:** 제목, 점수, 시간, 음소거 토글. 시간은 숫자와 축소되는 링을 함께 표시한다.
2. **작품 캔버스 43%:** 16×16 레시피, 상승 펠릿, 완성 연출. 정사각 영역을 유지하고 남는 공간은 배경으로 처리한다.
3. **진행률 7%:** `작품 완성 00%` 텍스트와 막대형 `progress`.
4. **팔레트 레인 14%:** 3×2 그리드의 6개 드롭 타깃. 각 레인은 최소 56px, 색·문양·한국어 이름과 **그 색의 채움률(`0–100%`)**을 함께 보여 준다(원본의 레인별 퍼센트 표기를 유지).
5. **펠릿 보드 20%:** 현재 배치 3개와 다음 배치 잔량. 배치 타깃은 최소 64px이다.
6. **하단 7%:** 한 줄 튜토리얼/피드백과 safe-area 여백. 결과 오버레이는 작품 캔버스부터 하단까지 덮되 상단 점수는 유지한다.

### 포인터·터치·키보드

- 마우스와 터치는 `PointerEvent` 하나로 처리한다. `pointerdown`에서 배치를 캡처하고, 8px 이동 후 드래그를 시작하며, `pointerup`에서 포함 중인 레인을 판정한다. 좌표는 매 이동마다 DOM을 재측정하지 않고 드래그 시작 시 캐시한다.
- 드래그 중 원본 배치는 45% 투명도, 유령은 포인터보다 18px 위로 표시해 손가락에 가리지 않게 한다. 유효한 레인은 윤곽과 라벨이 동시에 강조된다.
- 키보드는 `Tab`으로 배치·레인·버튼을 순환한다. 배치에서 `Enter/Space`로 집고, `←/→/↑/↓`로 6개 레인 간 선택을 이동하며, `Enter/Space`로 놓고, `Escape`로 취소한다. 숫자 `1–6`은 집은 배치를 해당 레인에 즉시 놓는 단축키다.
- `touch-action: none`은 드래그 보드에만 적용하고 페이지의 나머지 영역은 스크롤을 허용한다. 모든 상호작용 타깃은 44×44px 이상이다.

## 5. 상태·성능 모델

### 상태

`BOOT → READY → TUTORIAL → PLAYING → WIN | FAIL → RESULT`의 단방향 상태 머신을 쓴다. 탭이 백그라운드로 가면 `PAUSED`로 전환해 타이머·애니메이션·음원을 멈추고, 복귀 시 직전 상태로 돌아간다. 입력은 `TUTORIAL/PLAYING`에서만 판정한다.

- `game`: 상태, 시드, 남은 시간, 점수, 콤보, 오답 수, 시작 시각.
- `recipe`: 현재 도안 ID(`A|B`), 16×16 셀의 색 ID·완성 여부, 색별 미완성 인덱스, 완성 셀/전체 셀.
- `batches`: 15개 결정론적 큐, 화면에 노출된 3개, 선택·드래그 상태.
- `lanes`: 6개의 색 ID·문양·색별 채움률·DOM 경계 캐시·강조 상태.
- `particles`: 고정 길이 96 풀의 활성 여부, 시작/종료 좌표, 진행률, 색 ID, 시드 오프셋.

### 렌더링·성능

- 픽셀 작품과 파티클은 하나의 Canvas 2D에, UI·버튼·진행률은 HTML/CSS에 둔다. Canvas는 표시 크기가 바뀐 때만 재계산하고 DPR은 2로 제한한다.
- 아이들 시에는 정적 캔버스만 그리며, 파티클·완성 연출 중에만 `requestAnimationFrame`을 유지한다. 프레임 시간으로 위치를 계산해 중간 프레임 누락이 게임 상태를 바꾸지 않게 한다.
- 점수·셀 완성 판정은 입력 핸들러의 순수 로직으로 즉시 확정하고, 파티클은 결과를 뒤따라가는 연출로 분리한다. 배치 큐와 레시피는 시드 RNG로 재현 가능하게 만든다.
- 품질 기준은 최소 지원 기기에서 플레이 중앙값 50fps 이상, 하위 5% 프레임 30fps 이상, 초기 스크립트+스타일+마크업 gzip 180KB 이하, 외부 요청 0개다.

## 6. 원본 에셋·모션·오디오

- 레시피 맵과 배치 순서는 JavaScript 배열과 시드 RNG로 생성한다. 픽셀, 펠릿, 문양, 배경 점 패턴은 Canvas/CSS로 직접 그리며 외부 이미지·폰트·라이브러리를 요청하지 않는다.
- 표준 모션은 선택 90ms, 레인 스냅 140ms, 펠릿 상승 320ms, 셀 채움 120ms, 오답 흔들림 160ms, 승리 파동 1.2초다. 채움 연출이 종료되기 전에도 다음 배치를 조작할 수 있다.
- 음원은 첫 사용자 제스처 후 Web Audio API로 합성한 `집기 클릭`, `상승 휘쉬`, `콤보 톤`, `오답 버즈`, `완료 3음`만 사용한다. 자동 재생·배경음은 없고, 음소거 선택은 `localStorage`에 저장한다.
- 브라우저가 Web Audio를 제공하지 않거나 오디오 초기화가 거부되어도 플레이와 합격 판정은 영향을 받지 않는다.

## 7. 접근성·모션 축소

- 게임 제목은 `h1`, 점수·시간은 텍스트, 작품 진행률은 `progress`, 배치와 레인은 유의미한 `button` 요소로 구성한다. Canvas에는 현재 작품 완성도를 설명하는 대체 텍스트를 제공한다.
- `aria-label`은 `파란색 물결 펠릿 7개`, `파란색 물결 레인`처럼 색·문양·수량을 함께 읽는다. 색상 대비는 WCAG AA를 목표로 하고 키보드 포커스 링을 항상 표시한다.
- 정답·오답·완성은 색, 문양, 텍스트, 선택적 음을 조합해 알린다. `aria-live="polite"`는 `정답, 53% 완성`, `오답, 2초 감소`처럼 판정 단위로만 갱신하고 개별 파티클은 읽지 않는다.
- `prefers-reduced-motion: reduce`에서는 자동 호흡, 흔들림, 파동, 펠릿 비행을 제거하고 레인 80ms 밝힘 후 셀을 즉시 채운다. 타이머, 점수, 입력 판정은 표준 모드와 같다.
- 음소거 제어와 재시작은 항상 키보드 접근이 가능하고, 아이콘 단독이 아닌 텍스트 라벨을 가진다.

## 8. 반응형 행동

- **320×568px 이상 세로형:** 3×2 레인, 3개 배치를 유지하되 작품을 최대 224px로 축소하고 보조 텍스트를 한 줄로 제한한다. 세로 스크롤 없이 코어 플레이가 보여야 한다.
- **360–440px 세로형:** 기준 레이아웃. 루트는 `width: min(100%, 440px)`로 중앙 정렬한다.
- **넓은 세로형/데스크톱:** 게임 영역을 최대 440px로 유지하고 배경 패턴만 확장한다. 드래그 거리가 늘어나지 않는다.
- **가로형 또는 높이 520px 미만:** 2열로 전환해 작품·진행률을 왼쪽, 레인·펠릿 보드를 오른쪽에 둔다. 상단 정보는 전체 너비를 쓴다.
- `env(safe-area-inset-*)`를 상하좌우 여백에 반영하고, `ResizeObserver`로 루트 크기가 바뀔 때만 Canvas와 드롭 경계를 갱신한다.

## 9. 단독 구현 아웃라인

위치는 `games/pixel-pour/`이며 공유 파일, 빌드 도구, CDN, 외부 런타임 의존성을 사용하지 않는다. 로컬 정적 서버에서 `games/pixel-pour/index.html`을 열면 다른 게임과 무관하게 실행되어야 한다.

### `index.html`

- 언어·뷰포트·테마 메타, 제목, HUD, Canvas, `progress`, 6개 레인, 3개 배치 버튼, 힌트/라이브 리전, 결과 `dialog`의 시맨틱 마크업.
- `style.css`와 `script.js`만 상대 경로로 로드하고, Canvas 미지원 안내 문구를 포함한다.

### `style.css`

- CSS custom properties로 팔레트·간격·폰트 크기를 집중 관리하고, 시스템 폰트만 사용한다.
- 세로/가로 그리드, safe-area, 포커스, 드래그 상태, 결과 오버레이, 색각 문양, `prefers-reduced-motion` 규칙을 담는다.

### `script.js`

- `CONFIG/RECIPE/PALETTE` 상수, 시드 RNG, 상태 머신, 배치 생성기, 정답·점수 순수 함수, 입력 컨트롤러, Canvas 렌더러, 파티클 풀, 오디오 합성기, UI·ARIA 동기화, 리사이즈·가시성 핸들러를 모듈형 클래스/함수로 구분한다.
- 글로벌은 즉시 실행 함수 안에 감추고 `DOMContentLoaded`에서 한 번만 초기화한다. 플레이어 결과는 외부로 전송하지 않는다.

## 10. 인수 시나리오

1. **첫 플레이:** 새 세션에서 페이지를 열면 튜토리얼과 3개 배치가 보이고 시간은 38초에 멈춰 있다. 첫 배치를 집으면 힌트가 사라지고 타이머가 시작된다.
2. **정답 드롭:** 파란색·물결 배치를 파란색·물결 레인에 놓으면 배치가 소모되고, 6–8개 셀·전체 %·**해당 레인의 색별 채움률**·점수·콤보가 한 번만 갱신되며, 다음 배치가 보충된다.
3. **오답과 취소:** 다른 레인에 놓으면 75점·2초·콤보가 규칙대로 변하고 배치는 남는다. 레인 밖에 놓거나 `Escape`를 누르면 점수·시간이 변하지 않는다.
4. **키보드 완주:** 포인터 없이 `Tab`, `Enter/Space`, 화살표 또는 `1–6`, `Escape`만으로 배치 선택부터 성공/실패 후 재시작까지 완료할 수 있다.
5. **승리 경계:** 마지막 배치가 남은 시간 0에 드롭되면 그 판정을 끝낸 후 100%면 승리, 아니면 실패다. 결과가 중복 호출되지 않는다.
6. **실패·재시작:** 100% 전에 시간이 끝나면 미완성 안내와 재시작 버튼이 보인다. 재시작 후 점수·시간·콤보·셀·파티클·라이브 리전이 한 번에 초기화되고, **도안이 A↔B로 교대되어도 배치 15개·타이머 38초·판정 규칙은 그대로**다.
7. **중단·복귀:** 플레이 중 탭을 숨기면 시간과 파티클이 멈추고, 5초 후 복귀해도 숨기기 전과 같은 남은 시간에서 계속한다.
8. **접근성:** 색을 회색조로 보거나 음을 꺼도 문양·텍스트·포커스만으로 정답을 판별할 수 있고, 상태 변화가 라이브 리전에 한 번만 전달된다.
9. **모션 축소:** OS 모션 축소에서 펠릿 비행·흔들림·파동이 없어도 모든 판정·점수·완성 표시가 동일하다.
10. **반응형:** 320×568, 360×640, 390×844, 768×1024, 844×390에서 타깃이 중첩·잘림되지 않고 결과까지 플레이할 수 있다.
11. **독립성:** 네트워크를 차단한 로컬 서버에서 해당 폴더의 세 파일만으로 실행되고 콘솔 오류와 외부 요청이 0개다.

## 11. 테스트 계획

- **로직 테스트:** 고정 시드에서 **도안 A·B 각각** 배치 15개의 셀 합이 그 도안의 전체 셀 수(A=105, B=100–108)와 일치하는지, 각 배치의 정답 레인이 있는지, 셀이 중복 채워지지 않는지, 점수·콤보·시간 경계값과 0초 동시 판정을 개발 모드 `console.assert` 모음으로 검증한다.
- **입력 테스트:** 마우스, iOS/Android 터치, 키보드 전용으로 정답·오답·취소·빠른 연속 입력·드래그 중 `pointercancel`을 검증한다. 하나의 배치가 두 번 소모되지 않아야 한다.
- **브라우저 테스트:** 최신과 한 버전 전 Chrome/Safari/Firefox/Edge에서 스모크 테스트를 수행하고 iOS Safari와 Android Chrome에서 실기기를 확인한다.
- **시각·접근성 테스트:** 뷰포트 5종, 200% 텍스트 확대, 회색조, 고대비, 모션 축소, 스크린리더(VoiceOver 또는 NVDA), 키보드 포커스 순서를 점검한다.
- **성능·안정성 테스트:** 6배 CPU 슬로틀링과 중급 Android 실기기에서 50fps 중앙값/30fps 하위 5% 기준을 확인한다. 30회 재시작, 탭 중단·복귀, 리사이즈 반복 후 타이머·RAF·오디오·포인터 캡처가 중복·누수되지 않는지 확인한다.
- **패키지 테스트:** 외부 요청, 공유 파일, 콘솔 오류가 0개인지, gzip 합계가 180KB 이하인지, 오디오·Canvas 미지원 시에도 핵심 조작이 망가지지 않는지 확인한다.
