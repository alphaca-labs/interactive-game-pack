## 1. 한 줄 약속과 범위

주문표(ORDERS)가 요구하는 요리를 4×4 보드에서 골라 하단 트레이로 보내고, 같은 요리 3개가 모이면 주문이 완료되어 코인을 얻는다. 트레이가 넘치기 전에 주문 5장을 처리하는, 한 손 탭만으로 30~45초 안에 승패까지 끝나는 세로형 HTML5 미니게임이다.

- 근거: 프레임에서 확인되는 **상단 ORDERS 티켓 5장(코인 20/50/100/200/500)**, **빈 칸 1개가 있는 4×4 요리 보드(일부 칸은 타일이 겹쳐 쌓여 있음)**, **하단 곡선 컨베이어 트레이**를 재해석한다.
- 범위: 한국어 단일 레벨, 시드 기반 무작위 배치, 시작 안내, 성공/실패 결과, 코인 점수, 다시 하기, 데모 CTA.
- 비범위: 원본 게임의 로고·캐릭터·UI 캡처·음원 사용, 외부 SDK·분석·광고 연동, 서버 저장, 부스터(되돌리기·셔플·추가 칸), 추가 레벨·다국어.
- 확인되지 않은 규칙(코인 정확한 산식, 티켓 만료, 부스터 유무)은 프레임에 근거가 없으므로 **본 프로토타입의 독자 설계**임을 문서와 결과 화면 각주에 명시한다.

## 2. 30~45초 코어 루프

1. **준비(0~2초)**: 보드·트레이·주문표가 채워진 채로 열리고 “주문에 맞는 요리를 눌러 트레이로 보내세요”와 첫 주문의 요리 아이콘이 강조된다. 첫 유효 입력에 안내가 사라지고 타이머가 시작된다.
2. **처리(약 25~40초)**: 보드 타일을 탭 → 타일이 트레이의 다음 빈칸으로 이동 → 트레이에 같은 요리 3개가 모이면 즉시 제거되고 해당 요리를 요구하던 주문표가 완료되어 코인이 오른다. 완료된 티켓 자리에는 대기 티켓이 슬라이드로 들어온다.
3. **판정(약 1초)**: 주문 5장을 모두 완료하면 승리, 트레이 6칸이 모두 찬 채로 3개 매칭이 성립하지 않으면 실패, 시간이 0이 되어도 실패한다.
4. **결과(3초 이상)**: 획득 코인·완료 주문 수·남은 시간·최고 콤보를 보여 주고 `다시 주문받기`와 비상업적 `다른 데모 보기` CTA 를 제공한다. 자동으로 닫히지 않는다.

정상 라운드는 40초 타이머 안에서 끝나며 시작·결과 전환을 합쳐 약 30~45초를 목표로 한다.

## 3. 보드·트레이·주문 규칙

### 보드

- **4열×4행 16칸**. 각 칸은 타일 **0~2장**을 쌓을 수 있고 최상단 1장만 선택 가능하다(프레임의 겹친 타일 연출 근거). 아래 타일은 반투명 테두리와 “+1” 배지로 존재를 알린다.
- 한 판의 총 타일 수는 **24장 = 요리 8종 × 3장**이다. 배치는 15칸 1층 + 8칸 2층 + 빈 칸 1개(프레임의 점선 빈 칸)로 시작한다.
- 각 요리가 정확히 3장씩 존재하므로 **올바르게 모으면 항상 해결 가능**하다. 생성기는 “2층 타일 3장이 같은 요리로 완전히 가려지는” 배치를 거부해 데드락 없는 시드만 채택한다.
- 시드 PRNG + Fisher–Yates 로 섞고 `?seed=` 로 동일 보드를 재현한다. 첫 판은 1번 주문 요리의 3장을 모두 1층에 두어 튜토리얼 성공을 보장한다.

### 트레이

- 곡선 컨베이어 형태의 **슬롯 6칸**. 타일은 왼쪽부터 채워지고 같은 요리끼리 인접하도록 자동 정렬해 매칭 여부를 눈으로 읽을 수 있게 한다.
- 트레이에 같은 요리 3장이 모이면 **자동으로 제거**되고 뒤 슬롯이 앞으로 당겨진다.
- 한 번의 이동·정렬·매칭·판정이 끝날 때까지 입력을 잠근다(연타·중복 포인터 이벤트 방어).
- **판정 순서**: 타일 이동 → 정렬 → 3개 매칭 제거 → 주문 완료 확인 → 승리 확인 → 트레이 만석 실패 확인. 여섯 번째 타일로 매칭이 성립하면 실패하지 않는다.

### 주문표(ORDERS)

- 상단에 **동시 3장 노출 + 대기 2장**, 총 5장을 한 판에 처리한다. 각 티켓은 서로 다른 요리 1종과 코인 보상 **20 / 50 / 100 / 200 / 500** 을 가진다(프레임의 표기 그대로, 소수점 `.0` 표기는 쓰지 않는다).
- 3장 매칭이 제거되는 순간, 노출 중인 티켓 중 그 요리를 요구하는 티켓이 있으면 완료 처리하고 코인을 지급한다. 요구 티켓이 없으면 **정리 보너스 10코인**만 준다.
- 티켓은 만료되지 않는다. 압박은 트레이 잔여 칸과 타이머가 담당한다.
- 티켓 요리는 항상 보드에 3장이 남아 있는 요리 중에서 뽑아, 노출된 티켓이 달성 불가능해지지 않게 한다.

## 4. 점수·승리·실패

- 시작 시간 **40초**. 남은 시간은 막대와 숫자로 함께 표시한다.
- 코인: 티켓 완료 시 티켓 보상, 비티켓 3매칭 시 10코인. **연속 콤보**(직전 매칭 후 4초 이내 다음 매칭)마다 보상 ×1.0 → ×1.2 → ×1.5(상한).
- 승리: 주문 5장을 모두 완료. `floor(남은 초) × 5` 시간 보너스를 **한 번만** 더한다.
- 실패 A: 트레이 6칸이 찬 상태로 매칭 판정 후에도 제거가 없을 때.
- 실패 B: 남은 시간이 0이 되었을 때.
- 동시 판정 우선순위: 마지막 티켓 완료와 타이머 만료가 같은 프레임이면 **입력 핸들러의 승리 확정이 우선**하고 이후 틱은 무시한다. 승패는 `finishOnce(result)` 로 단 한 번만 기록한다.
- 코인은 0 미만으로 내려가지 않으며, 잘못 보낸 타일에 대한 코인 차감 페널티는 두지 않는다(실수 페널티는 트레이 칸 소모 자체다).
- 다시 하기는 새 시드·새 배치·새 티켓 구성으로 시간·코인·콤보·포커스를 모두 초기화한다.

## 5. 장면과 레이아웃

세로 화면을 위에서 아래로 네 영역으로 구성한다.

1. **헤더**: 오리지널 워드마크 `ORDER TRAY`, 코인 HUD(아이콘 + 숫자), 음소거 토글.
2. **주문표 띠**: 티켓 3장 노출(요리 아이콘 + 한국어 명칭 + 코인), 대기 티켓 2장은 축소·반투명으로 뒤에 겹쳐 남은 개수를 보여 준다. 완료 티켓은 도장 표식 후 250ms 만에 슬라이드 아웃한다.
3. **보드**: 둥근 파란 프레임 안 4×4 버튼 그리드. 각 칸은 최소 44×44px, 2층 칸은 그림자·오프셋·“+1” 배지로 깊이를 표현한다.
4. **트레이**: 곡선 컨베이어 위 슬롯 6칸과 진행 방향 화살표. 잔여 칸이 2개 이하로 떨어지면 테두리 경고 색과 “트레이 여유 2칸” 문구를 동시에 노출한다.

배경은 프레임의 벚꽃·하늘 톤을 참고하되 CSS 그라디언트와 도형으로 새로 그린 오리지널 장면을 쓴다. 결과 카드는 같은 화면 위 모달로 겹치되 장면 맥락이 보이도록 부분 투명 배경을 사용한다.

## 6. 입력 설계

- **포인터**: `click` 을 단일 확정 이벤트로 사용한다. hover 는 장식이며 선택 조건이 아니다.
- **터치**: 셀 전체가 타깃이고 `touch-action: manipulation` 으로 더블탭 확대·탭 지연을 줄인다. 드래그를 요구하지 않는다.
- **키보드**: 보드 진입 시 첫 선택 가능 칸에 포커스. 방향키로 4×4 좌표 이동(경계에서 머무름), `Enter`/`Space` 로 전송, `R` 재시작, `M` 음소거. 주문표·트레이는 `aria` 정보만 제공하고 포커스 순환에는 포함하지 않는다.
- 포인터·터치·키보드는 모두 같은 `sendTile(cellId)` 경로를 사용해 규칙 차이를 만들지 않는다.
- 결과 모달은 포커스를 제목으로 옮기고 `Tab` 을 두 CTA 안에 유지한다. `Escape` 로 닫히지 않으며 재시작 시 보드 첫 칸으로 포커스를 돌린다.

## 7. 상태 모델

```text
BOOT → READY → PLAYING → RESOLVING → WON
                            └──────→ LOST
WON/LOST ── replay ──→ READY
```

- `BOOT`: DOM·SVG 심볼·오디오 설정 준비.
- `READY`: 시드 생성, 24타일 배치 검증, 티켓 5장 구성, `40.0s / 0코인 / 0-5주문` 초기화. 첫 유효 입력으로 `PLAYING`.
- `PLAYING`: 타이머·입력 활성. 셀 상태는 `stack(0..2) | empty`, 트레이 슬롯 상태는 `empty | filled | clearing`.
- `RESOLVING`: 승리·실패 조건 성립 시 한 번만 진입하는 원자적 구간. 타이머·입력을 즉시 중단한다.
- `WON`/`LOST`: 결과·CTA 표시, 보드 비활성. `restart()` 만 `READY` 로 되돌린다.

핵심 데이터는 `{phase, seed, cells, tray, tickets, queue, coins, combo, comboUntil, timeMs, muted}` 한 객체로 관리한다. 렌더는 상태를 읽기만 하고, 타이머는 `performance.now()` 경과 기준으로 계산해 백그라운드 탭 누적 오차를 막는다. 탭이 숨겨지면 일시정지하고 복귀 시 안내 후 재개한다.

## 8. 절차적·오리지널 에셋

- 요리 아이콘 **12종**(라멘, 새우, 초밥, 연어, 롤, 튀김, 국, 덮밥, 도시락, 만두, 어묵, 계란말이)을 원·사각·path 조합의 인라인 SVG 로 자체 제작하고, 한 판에는 그중 8종을 뽑아 쓴다.
- 각 아이콘은 색상 외에 **고유 실루엣 + 내부 무늬 + 2~4자 한국어 명칭**을 가져 색각에만 의존하지 않는다. 원본 게임의 사실적 3D 렌더 스타일은 모방하지 않고 평면 벡터 톤으로 새로 그린다.
- 티켓(톱니 모서리 종이), 코인, 컨베이어 곡선, 보드 프레임, 벚꽃·하늘 배경은 CSS gradient·pseudo-element·인라인 SVG 로 만든다.
- 외부 이미지·웹폰트·CDN·라이브러리 요청이 0건이다. 무료 에셋을 쓰게 되면 CC0/OFL 만 사용하고 `ASSETS.md` 에 출처를 남긴다(현 계획에서는 전량 오리지널 제작 전제).

## 9. 모션과 오디오

- 전송: 타일이 보드 칸에서 트레이 슬롯까지 320ms 곡선 이동, 착지 시 60ms 눌림.
- 매칭: 3장 180ms 확대 → 220ms 코인 HUD 방향으로 흡수, 티켓 도장 250ms.
- 경고: 잔여 칸 2 이하일 때 트레이 테두리 1.2초 주기 펄스(감소 모션에서는 정적 색·문구로 대체).
- Web Audio API 로 전송 1음, 매칭 3음, 티켓 완료 상승 2음, 실패 낮은 1음만 합성한다. 사용자 입력 이후에만 AudioContext 를 열고 배경음은 없다.
- 음소거 토글은 항상 노출하며 `localStorage` 에 저장하되 저장 실패 환경에서도 정상 동작한다. 소리는 보조 채널이며 모든 정보는 텍스트·도형으로도 전달한다.

## 10. 접근성

- 보드 칸은 실제 `button` 이며 `aria-label="{행}행 {열}열, {요리명}, 남은 층 {n}"`, 선택 불가 칸은 `disabled`.
- 주문표는 목록 시맨틱으로 제공하고 `aria-live="polite"` 로 **주문 완료·트레이 잔여 2칸 이하·라운드 종료**만 알린다. 매초 타이머는 읽지 않고 10초·5초만 알린다.
- 명암비 텍스트 4.5:1, 비텍스트 상태 경계 3:1 이상. `:focus-visible` 3px 윤곽선.
- 색만으로 요리·상태를 구분하지 않고 아이콘·명칭·배지를 병용한다.
- `prefers-reduced-motion: reduce` 에서 이동·펄스·입자를 제거하고 즉시 상태 변경과 정적 결과 카드로 같은 정보를 준다. `forced-colors` 에서 배경 장식을 숨기고 시스템 색 테두리를 남긴다.

## 11. 반응형 동작

- `viewport-fit=cover` + safe-area inset, `min-height: 100dvh`.
- 320×568 부터 데스크톱까지 가로 스크롤 없이 동작한다. 콘텐츠 폭 `min(100% - 24px, 560px)`.
- 4×4 보드와 트레이 6칸 구조는 모든 크기에서 유지한다. 셀 `clamp(44px, 17vw, 88px)`, 트레이 슬롯 `clamp(40px, 14vw, 72px)`, 간격·글꼴은 `clamp()`.
- 높이 650px 미만에서는 헤더 장식과 대기 티켓 미리보기를 축소하고 보드·트레이·CTA 를 우선 노출한다.
- 가로 화면에서는 최대 폭 820px 2열 셸(좌: 주문표+HUD, 우: 보드+트레이)을 쓰되 DOM 순서와 키보드 좌표는 유지한다.
- 회전·리사이즈 중 남은 시간, 코인, 배치, 트레이 내용, 포커스 칸을 보존한다.

## 12. 독립 파일 구현 개요

경로는 `games/order-tray/` 이며 아래 3개 파일만 사용한다. 다른 게임이나 공용 파일을 import 하지 않는다.

### `index.html`
- viewport·테마 메타, 의미 있는 `main`, 헤더/코인 HUD, 주문표 영역, 16칸 보드 컨테이너, 트레이 6슬롯, 안내 live region, 결과 모달 마크업, `noscript` 안내.
- `style.css`·`script.js` 를 상대 경로로만 연결한다.

### `style.css`
- 로컬 시스템 글꼴, 색·간격·그림자 CSS 변수, 벚꽃 배경·티켓·컨베이어의 절차적 장식.
- 4×4 그리드, 2층 타일 깊이 표현, 트레이 슬롯, 포커스·경고·완료·결과 상태, safe area, 가로/저높이 미디어 쿼리.
- `prefers-reduced-motion`·`prefers-contrast`·`forced-colors` 대체 스타일.

### `script.js`
- `DISHES` 원본 데이터와 SVG 생성기, 시드 PRNG/Fisher–Yates, `createRound`(데드락 없는 배치 검증 포함), `sendTile`, `resolveTray`, 코인·콤보 계산, 단조 시계 타이머, 상태 전이·렌더 함수.
- click/keydown/visibilitychange/resize 처리, 포커스 관리, 음소거·Web Audio 합성, 저장소 실패 방어.
- 중복 종료를 막는 `finishOnce(result)`, 애니메이션 중 입력 잠금, `?seed=` 재현, `?test=1` 순수 함수 console assertion.

`file://` 로 직접 열어도 네트워크 요청·CORS 오류 없이 한 라운드와 재시작이 완결되어야 한다.

## 13. 인수 시나리오

1. **정상 승리** — Given 새 라운드, When 주문 5장의 요리를 각각 3장씩 트레이로 보내면, Then 티켓 5장이 순서대로 완료되고 승리 결과에 코인 합계와 시간 보너스가 한 번만 표시된다.
2. **비티켓 매칭** — Given 노출 티켓이 요구하지 않는 요리 3장을 모으면, Then 즉시 제거되고 10코인이 지급되며 티켓 진행에는 영향이 없다.
3. **여섯 번째 안전판** — Given 트레이가 5칸 찬 상태, When 여섯 번째 타일이 3매칭을 완성하면, Then 실패하지 않고 제거·정렬 후 3칸이 비워진다.
4. **오버플로 실패** — Given 트레이 5칸이 서로 다른 요리로 찬 상태, When 매칭되지 않는 여섯 번째 타일을 보내면, Then 실패 결과가 열리고 이후 보드 입력은 코인·시간을 바꾸지 않는다.
5. **시간 실패** — Given 주문 4장 완료, When 남은 시간이 0이면, Then 실패 결과가 열린다.
6. **경계 동시성** — Given 마지막 티켓 완료와 타이머 만료가 같은 프레임에 예약됨, When 입력 핸들러가 먼저 완료를 확정하면, Then 승리만 한 번 기록된다.
7. **2층 타일** — Given 2층 칸, When 최상단을 보내면, Then 아래 타일이 드러나 선택 가능해지고 `aria-label` 의 남은 층 수가 갱신된다.
8. **해결 가능성** — Given 임의의 100개 시드, When 자동 검증을 돌리면, Then 모든 시드에서 요리별 타일 수가 3의 배수이고 완전 가림 데드락이 0건이다.
9. **재시작** — Given 승패 결과, When 다시 주문받기를 누르면, Then 새 배치·새 티켓으로 시간·코인·콤보·트레이가 초기화되고 첫 보드 칸에 포커스가 간다.
10. **키보드 완주** — Given 마우스 없음, When 방향키와 Enter/Space 만 사용하면, Then 전체 라운드를 완주할 수 있다.
11. **독립 실행·반응형** — Given 네트워크 차단, 320×568·390×844·844×390·1440×900 뷰포트, When 직접 파일로 실행·회전하면, Then 외부 요청 0건, 가로 스크롤·가려진 조작·상태 초기화가 없다.

## 14. 테스트 계획

- **규칙 단위**: 시드별 24타일/8종×3장 구성, 2층 배치 검증, 3매칭 제거, 티켓 매칭·보너스 분기, 콤보 상한, 시간 보너스, 코인 하한.
- **상태 전이**: 첫 입력 시작, 연타 잠금, 애니메이션 중 재입력, 오버플로/시간 만료/마지막 티켓 경쟁, `finishOnce`, 재시작 초기화, visibility 일시정지를 가짜 시계로 확인.
- **입력**: Chrome/Safari 마우스, iOS/Android 터치 에뮬레이션, 방향키·Enter·Space·R·M, 포커스 트랩·복귀.
- **접근성**: 키보드 전용, VoiceOver, 200% 확대, reduced motion, forced colors, 음소거에서 정보·조작 동등성.
- **레이아웃/성능**: 4개 뷰포트·회전에서 겹침·스크롤 확인, 보급형 모바일 에뮬레이션에서 매칭 애니메이션 중 긴 작업 없이 입력 즉시 반응.
- **독립성**: Network offline 로 파일 직접 실행, 404·외부 요청·console error 0건, 재시작 20회 후 타이머·이벤트 리스너 중복 0건.

## 15. 일정·견적 근거

| 항목 | 공수 | 내용 |
|---|---:|---|
| 로직·상태·입력 | 3.0일 | 시드 배치 + 데드락 검증, 2층 스택, 트레이 정렬·매칭, 티켓 큐, 코인·콤보, 타이머 경쟁 방어, 키보드·터치, 재시작 |
| 오리지널 아트·UI·모션 | 2.0일 | 요리 SVG 12종, 티켓·컨베이어·배경 장면, 반응형, 감소 모션, 합성 효과음 |
| QA·튜닝 | 1.5일 | 뷰포트·접근성·오프라인 회귀, 트레이 칸수/타이머/티켓 난이도 조정 |
| **합계** | **6.5 인·일** | |

기획 정리·내부 확인·1회 수정 버퍼를 포함해 **영업일 7~10일**, 유형 B 범위 **₩6.5M~₩9.0M(VAT 별도)** 로 본다. 첫 타이틀로 착수하는 경우 공용 셸(빌드 없는 3파일 템플릿, 접근성·반응형 기본값, 결과 모달 패턴) 구축 **+2일** 이 추가된다.

**변동 위험 3가지**

1. **해결 가능성 보장** — 2층 스택과 3매칭이 결합되면 “같은 요리 3장이 서로를 가려 데드락” 이 생길 수 있다. 배치 생성기의 거부 조건과 100시드 자동 검증으로 방어하며, 실패 시 폴백은 전량 1층 배치(15타일 5트리플, 난이도 하향)다.
2. **트레이 용량 튜닝** — 6칸은 관대하고 5칸은 가혹하다. 내부 플레이 데이터로 승률 55~70% 구간을 찾고, 튜닝 상수는 `script.js` 상단 한곳에 모아 수정 비용을 1시간 이내로 유지한다.
3. **아이콘 변별력** — 일식 소재는 실루엣이 서로 비슷하다. 한 판에 뽑히는 8종은 실루엣 그룹이 겹치지 않도록 배타 규칙을 두고, 명칭 라벨을 항상 병기한다.
