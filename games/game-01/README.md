# 게임 1 — 오더 트레이 (Order Tray)

작업 항목 1/8 · 슬러그 `order-tray` · 유형 **B — 보드상태 퍼즐** · 출처 영상 `00:06` 4종 중 1번
기획 SSOT: `outputs/plans/order-tray.md` · 데이터 SSOT: `outputs/work-items.json` 항목 1

## 실행

`index.html` 을 브라우저로 직접 열면 된다. 빌드·서버·의존성이 없고 `file://` 에서 완결된다.

| 쿼리 | 용도 |
|---|---|
| `?seed=12345` | 같은 보드를 재현한다 |
| `?test=1` | 순수 함수 자동 검증(100시드 배치 + 규칙 단위 + 최악 플레이 시뮬레이션)을 콘솔에 출력한다 |

콘솔에서 `OrderTray.runTests()` 로도 같은 검증을 돌릴 수 있다.

## 규칙

- 4×4 보드 16칸에 타일 24장(요리 8종 × 3장). 9칸은 2층이고 최상단 1장만 선택 가능하며, 빈 칸이 1개 있다.
- 타일을 누르면 하단 트레이(6칸)로 이동한다. 트레이에 같은 요리 3장이 모이면 자동 제거된다.
- 제거된 요리를 요구하는 주문 티켓이 노출 중이면 완료되고 보상 코인(20/50/100/200/500)을 준다. 없으면 정리 보너스 10코인.
- 콤보: 직전 매칭 후 4초 이내에 다시 매칭하면 보상 배수가 ×1.0 → ×1.2 → ×1.5(상한)로 오른다.
- 승리: 주문 5장 완료(+ `남은 초 × 5` 보너스 1회). 실패: 트레이 6칸이 찬 채로 매칭 불성립, 또는 40초 경과.
- 판정 순서는 `이동 → 정렬 → 3매칭 제거 → 주문 완료 → 승리 → 만석 실패` 다. 6번째 타일이 매칭을 완성하면 실패하지 않는다.

## 조작

포인터 탭 / 터치 탭 / 키보드(방향키 이동, `Enter`·`Space` 전송, `R` 재시작, `M` 음소거). 세 경로 모두 같은 `sendTile()` 을 거쳐 규칙 차이가 없다.

## 밸런싱

`script.js` 최상단 `TUNING` 블록 한 곳에 모여 있다 — `TRAY_SLOTS`, `ROUND_MS`, `TILE_TYPES`, `COMBO_STEPS`, 티켓 보상, 콤보 창, 시간 보너스.

## 에셋

요리 아이콘 12종(라멘·국·덮밥·새우·어묵·초밥·도시락·롤·계란말이·연어·튀김·만두), 티켓·코인·컨베이어·보드·벚꽃 배경까지 전량 인라인 SVG 와 CSS 로 자체 제작했다. 외부 이미지·웹폰트·CDN·라이브러리·음원 요청이 0건이며, 효과음은 Web Audio API 합성음이다. 원본 영상의 로고·캐릭터·UI 캡처·음원은 사용하지 않았다.

## 기획서와 달라진 점

1. **보드 타일 수** — 기획서 3장 절의 `15칸 1층 + 8칸 2층` 은 합이 23장이라 같은 절의 `24장 = 8종 × 3장` 과 맞지 않는다. 해결 가능성의 근거가 되는 **요리별 3장** 불변식을 살려 `9칸 2층 + 6칸 1층 + 빈 칸 1개 = 24장` 으로 확정했다.
2. **데드락 방어를 더 강하게** — 기획서의 거부 조건("3장이 모두 가려짐") 대신, 배치 단계에서 **모든 요리가 최소 1장은 최상단**에 오도록 구성한다(첫 주문 요리는 3장 모두 최상단). 100시드 자동 검증이 이 불변식을 확인한다.
3. **주문 공급 안전장치(신규)** — 기획서대로 티켓 요리를 지연 배정하면, 플레이어가 주문에 없는 요리를 4종 넘게 정리했을 때 대기 티켓에 배정할 요리가 떨어져 **라운드가 조용히 클리어 불가**가 된다. 남은 요리가 대기 티켓 수보다 모자라지는 순간 그 매칭을 대기 티켓으로 승격해 처리한다(`pickTicketForClear`). 최악 플레이 시뮬레이션 100시드로 항상 주문 5장을 처리할 수 있음을 확인한다.
4. **결과 화면의 `다른 데모 보기`** — 공용 목록 페이지는 이 항목의 범위 밖이라 상위 경로로 이동시키지 않고, 안내 문구만 펼친다(끊긴 링크 방지).

코인 산식·콤보 배수·트레이 칸수(6)·제한 시간(40초)·티켓 만료 없음은 원본 영상에 근거가 없는 **본 프로토타입의 독자 설계**이며, 결과 화면 각주에도 명시했다.

## 검증 결과

`?test=1` 순수 함수 검증과 헤드리스 Chrome(CDP) E2E 25건을 모두 통과했다.

- 100시드 배치 불변식(요리별 3장 · 완전 가림 0건 · 첫 주문 요리 전부 최상단 · 실루엣 그룹 2종 제한), 시드 재현성, 트레이 정렬·3매칭 탐지, 콤보 상한·코인 하한, 최악 플레이 100시드 클리어 가능성
- 초기 렌더(16칸 · 6슬롯 · 티켓 3장 · 2층 9칸 · 빈 칸 1개), **외부 네트워크 요청 0건**, 콘솔 error 0건
- 12라운드 연속 플레이 전부 결과 화면으로 종료(그리디 플레이어 12승), 승리 시 5/5 주문·코인 획득
- 서로 다른 요리 6장 → 트레이 오버플로 실패, 결과 이후 보드 입력 무효, 재시작 초기화·포커스 복귀
- 방향키 포커스 이동 · `Enter` 전송, 음소거 토글
- 320×568 · 390×844 · 844×390 · 1440×900 에서 가로 스크롤 0 · 보드/트레이 구조 유지 · 셀 최소 44px

## 접근성

보드 칸은 실제 `button` 이고 `aria-label` 에 `행·열·요리명·남은 층` 을 담는다. 주문 완료·트레이 잔여 2칸 이하·10초/5초 경고·라운드 종료만 `aria-live="polite"` 로 알린다(매초 타이머는 읽지 않는다). 요리는 색 외에 실루엣·내부 무늬·한국어 명칭으로 구분한다. `prefers-reduced-motion`·`prefers-contrast`·`forced-colors` 대체 스타일을 제공한다.
